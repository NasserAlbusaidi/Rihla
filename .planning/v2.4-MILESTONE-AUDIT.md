## Publish Blockers

### 🔴 HARD BLOCKER 1 — Firebase not deployed

`firebase deploy --only firestore:rules,functions` has never been run.

The Phase 38+39 Firestore rules (deny cut modules) and Storage rules (deny-all on trip-documents/trip-memories/receipts) exist in source at `security/firestore.rules` and `security/storage.rules` — but they are **not live in production**. Any client connecting to the `rihla-system` Firebase project hits the old rules.

**Fix:** Run `firebase deploy --only firestore:rules,functions` from the repo root before any alpha release.

### 🔴 HARD BLOCKER 2 — Manual smoke test never done

Phase 39 SC5 explicitly deferred the manual smoke test on a fresh device install. This was a stated acceptance criterion and was marked ⏸.

The surviving golden path (anonymous auth → create group → join → create event → add expense → settle-up) has never been manually walked. 781 automated tests provide indirect coverage, but they run against mocked providers — not the real Firebase backend on a clean install.

**Fix:** Install the app on a clean Android device (no prior data), walk the golden path end-to-end.

### 🟡 SOFT BLOCKER 3 — Phase 37 dark theme on-device QA

Phase 37 VERIFICATION status is `human_needed`. Five success criteria pass at code level, but the verification explicitly requires:
- On-device theme toggle (System → Light → Dark) with shadow tint visual check
- 22-screen walkthrough in MANUAL-QA.md (stale — references deleted screens)
- Rapid toggle 5 times for flicker/ghosting check

The MANUAL-QA.md walkthrough references Gear, Logistics, Vault, and Memories screens that were deleted in Phase 39. The walkthrough must be pruned to match the current surface area before it can be completed.

**Fix:** Update MANUAL-QA.md to remove deleted screens, then run the walkthrough on-device.

### 🟡 SOFT BLOCKER 4 — Phase 36/38 have no VERIFICATION.md

Two phases are unverified by GSD standards:
- **Phase 36**: ARCH-01 (screen file LOC) and ARCH-04 (CacheService split) are still marked Open in the requirements traceability table. No independent evidence they were completed.
- **Phase 38**: INFRA-01 (Storage membership enforcement) has no formal verification. The integration test confirming "non-member cannot read/write trip bucket" (the Phase 38 SC) was never produced.

Note: For Phase 38 specifically, the Storage rules are deny-all (stronger than membership check), so the security outcome is covered — but not verified.
