**4. Create `security/` directory and `security/firestore.rules`:**
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Default: deny all
    match /{document=**} {
      allow read, write: if false;
    }

    // Invite codes: public read for joining, authenticated write
    match /inviteCodes/{code} {
      allow read: if true;
      allow write: if request.auth != null;
    }

    // Groups
    match /groups/{groupId} {
      // In-document membership check -- no get() call needed (D-14)
      function isMember() {
        return request.auth != null &&
               request.auth.uid in resource.data.memberIds;
      }

      function isValidGroupCreate() {
        return request.auth != null &&
               request.resource.data.name is string &&
               request.resource.data.name.size() > 0 &&
               request.resource.data.memberIds is list &&
               request.resource.data.currency is string;
      }

      allow read: if isMember();
      allow create: if isValidGroupCreate();
      allow update: if isMember();
      allow delete: if false;

      // Group subcollections -- ONE get() call to parent for membership
      match /{subcollection}/{docId} {
        function isGroupMember() {
          return request.auth != null &&
            request.auth.uid in
              get(/databases/$(database)/documents/groups/$(groupId)).data.memberIds;
        }
        allow read, write: if isGroupMember();
      }
    }
  }
}
```

Per D-14: memberIds is an array field, rules use `in` operator for O(1) lookup. Per D-15: rules deployed to emulator first, never production without tests passing.

The test file must:
- Import `initializeTestEnvironment`, `assertSucceeds`, `assertFails` from `@firebase/rules-unit-testing`
- Import `readFileSync` from `fs` to load the rules file at `../security/firestore.rules`

Test cases (minimum 8):
1. **"unauthenticated user cannot read group"** -- unauthenticatedContext().firestore().collection('groups').doc('group1').get() should fail
2. **"non-member cannot read group"** -- user 'user-nonmember' tries to read group where memberIds does not include their UID -- should fail
3. **"member can read group"** -- user 'user-member' reads group where memberIds=['user-member'] -- should succeed
4. **"authenticated user can create group with valid fields"** -- user 'user-creator' creates group with {name: 'Test', memberIds: ['user-creator'], currency: 'OMR', createdAt: ...} -- should succeed
5. **"cannot create group without name"** -- create group missing name field -- should fail
6. **"cannot create group without memberIds"** -- create group missing memberIds -- should fail
7. **"member can update group"** -- set up group with memberIds=['user-member'], then user 'user-member' updates it -- should succeed
8. **"nobody can delete group"** -- member tries to delete group -- should fail
9. **"member can read group subcollection document"** -- set up group with memberIds=['user-member'], then read from groups/group1/expenses/exp1 -- should succeed
10. **"non-member cannot read group subcollection"** -- user not in memberIds tries to read subcollection -- should fail
11. **"anyone can read invite codes"** -- unauthenticated read of inviteCodes/code1 -- should succeed
12. **"authenticated user can write invite codes"** -- authenticated write to inviteCodes/code1 -- should succeed

Important implementation details:
- Use `testEnv.authenticatedContext('uid')` to get Firestore for a specific UID
- Use `testEnv.unauthenticatedContext()` for anonymous access
- Use `testEnv.withSecurityRulesDisabled(async (context) => { ... })` to seed test data (set group documents with memberIds before testing reads)
- Call `testEnv.cleanup()` in afterAll
- Call `testEnv.clearFirestore()` in afterEach
