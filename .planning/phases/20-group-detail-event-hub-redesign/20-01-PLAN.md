Rebuild the GroupDetailScreen layout to match the Phase 20 design spec: 2x2 stats grid above the fold, settle-up CTA, event cards with left accent bars and inline personal balances, section reorder (Events > Members > Activity), and skeleton loading state. Satisfies SCRN-01.

### Task 01 — Infrastructure: Add animations dependency, extend GroupKeys, prepare tests
**Wave:** 0 | **Reqs:** SCRN-01
**Input:** Existing `pubspec.yaml`, `group_keys.dart`, `group_detail_screen_test.dart`
**Output:** Updated pubspec with `animations` dependency, extended GroupKeys, updated test file with corrected assertions and new test cases

**Steps:**
1. Run `flutter pub add animations` to add the `animations` package (version ^2.0.0) to pubspec.yaml. This is needed by Plan 02 for OpenContainer but must be added once in Wave 0. Per D-05.
2. Add the following keys to `lib/features/groups/keys/group_keys.dart`:
   - `static const statsGrid = Key('group_stats_grid');`
   - `static const statYourBalance = Key('group_stat_your_balance');`
   - `static const statGroupTotal = Key('group_stat_group_total');`
   - `static const statActiveMembers = Key('group_stat_active_members');`
   - `static const statEvents = Key('group_stat_events');`
   - `static const settleUpCta = Key('group_settle_up_cta');`
3. In `test/features/group_detail_screen_test.dart`:
   - The test `shows GroupBalanceHero when expenses exist` asserts `find.byKey(GroupKeys.groupBalancesLabel)`. This will break when GroupBalanceHero is removed and replaced with stats grid. Update this test to instead assert `find.byKey(GroupKeys.statsGrid)` — the stats grid should appear when expenses exist.
   - The test `hides GroupBalanceHero when no expenses exist (D-19)` asserts `find.byKey(GroupKeys.groupBalancesLabel)` is `findsNothing`. The stats grid is always visible (even with zero balances per D-08), so update this test: assert `find.byKey(GroupKeys.statsGrid)` is `findsOneWidget` and `find.byKey(GroupKeys.settleUpCta)` is `findsNothing` (hidden when zero balance per D-10).
   - The test `invite code section appears below events section (D-30)` already checks Events appears before Invite Code. Add a new test `section order: Events before Members before Activity (D-09)` that asserts `GroupKeys.eventsSection` Y < `GroupKeys.membersAndBalancesSection` Y < `GroupKeys.recentActivitySection` Y.
   - Add new test: `shows settle-up CTA when balance is non-zero` — pump with `_balancesWithExpenses`, assert `find.byKey(GroupKeys.settleUpCta)` is `findsOneWidget`.
   - Add new test: `hides settle-up CTA when all balances are zero` — pump with `_balancesEmpty`, assert `find.byKey(GroupKeys.settleUpCta)` is `findsNothing`.
   - Add new test: `stats grid shows 4 stat tiles` — pump with `_balancesWithExpenses`, assert `find.byKey(GroupKeys.statYourBalance)`, `find.byKey(GroupKeys.statGroupTotal)`, `find.byKey(GroupKeys.statActiveMembers)`, `find.byKey(GroupKeys.statEvents)` all findOneWidget.
   - Update the `_wrap` helper: it currently uses `MaterialApp(home: child)`. Since GroupDetailScreen calls `context.push(...)` via GoRouter, consider wrapping with `MaterialApp.router()` + a `GoRouter` that has the `/group/:gid` route (following Phase 19 P03 pattern). However, the existing tests work with `MaterialApp(home: child)` because no navigation tests fire. Keep `MaterialApp(home: child)` for now since no new tests navigate.

**Verify:** `flutter test test/features/group_detail_screen_test.dart` — some tests will fail (expected) because implementation is not yet updated. The new test cases should be compilable but some will fail red (TDD: red phase). Existing tests that were updated may also fail since the GroupBalanceHero is still present. This is acceptable — Wave 1 tasks will make them green.

### Task 02 — Create GroupStatsGrid widget and redesign EventCard
**Wave:** 1 | **Reqs:** SCRN-01
**Input:** `group_keys.dart` with new keys (from Task 01), existing `event_card.dart`, design spec
**Output:** New `group_stats_grid.dart` widget, updated `event_card.dart` with left accent bar + inline balance

**Steps:**
1. Create `lib/features/groups/widgets/group_stats_grid.dart` containing:
   - A `GroupStatsGrid` widget that takes: `Decimal userNetBalance`, `Decimal groupTotal`, `int activeMembers`, `int eventCount`, `String currency`.
   - Renders a `GridView.count(crossAxisCount: 2, shrinkWrap: true, physics: NeverScrollableScrollPhysics(), crossAxisSpacing: AppColors.space8, mainAxisSpacing: AppColors.space8, childAspectRatio: 1.6)` with 4 `StatCard` children.
   - Key the grid with `GroupKeys.statsGrid`.
   - Tile 1: "YOUR BALANCE" overline (decorative, textMuted OK), value = formatted balance with currency. `valueColor` determined by Dart 3 switch on `userNetBalance.compareTo(Decimal.zero)`: `< 0 => AppColors.errorText`, `> 0 => AppColors.successText`, `_ => AppColors.textPrimary`. Key: `GroupKeys.statYourBalance`.
   - Tile 2: "GROUP TOTAL" overline, value = formatted total with currency, default color. Key: `GroupKeys.statGroupTotal`.
   - Tile 3: "ACTIVE MEMBERS" overline, value = member count string. Key: `GroupKeys.statActiveMembers`.
   - Tile 4: "EVENTS" overline, value = event count string. Key: `GroupKeys.statEvents`.
   - Private `StatCard` widget inside the same file: `Container` with `AppColors.surface` background, `AppColors.border` border, `BorderRadius.circular(AppColors.radiusSmall)`, padding `AppColors.space12`. Column: overline Text (fontSize: 10, fontWeight: w700, color: AppColors.textMuted, letterSpacing: 0.5), SizedBox(height: 4), value Text (fontSize: 18, fontWeight: w800, color: valueColor).
   - Use `AppFormatters.formatCurrency(amount, currency)` for financial values.

2. Update `lib/features/events/widgets/event_card.dart` per D-01, D-02, D-03:
   - Add an optional `Decimal? personalBalance` parameter to EventCard constructor. This allows GroupDetailScreen to pass in the per-event balance for the current user.
   - Replace the existing Row layout (48x48 icon container + content column) with IntrinsicHeight Row:
     - Left accent bar: `Container(width: 3.0, decoration: BoxDecoration(color: event.isPast ? AppColors.textMuted : AppColors.primary, borderRadius: BorderRadius.horizontal(left: Radius.circular(AppColors.radiusLarge))))`.
     - Expanded content area with padding, containing: event name (titleMedium), date range (textSecondary, existing `_buildMetaText()` logic), personal balance line, expense count line.
   - Personal balance line (per D-01): If `personalBalance` is non-null and not zero, display using the Dart 3 switch pattern: `< 0 => ('You owe OMR ${abs.toStringAsFixed(3)}', AppColors.errorText)`, `> 0 => ('You are owed OMR ${toStringAsFixed(3)}', AppColors.successText)`, `_ => ('Settled', AppColors.textSecondary)`. If `personalBalance` is null, show the existing total spent line instead.
   - Expense count line: Show ` · N expenses` using `AppColors.textSecondary` (NOT textMuted -- functional text per WCAG rule).
   - Keep existing `Opacity(opacity: 0.6)` wrapper for past events (D-02) — already correct.
   - Keep TapBounce wrapper.
   - Remove the type badge chip (the small colored chip showing event type label) — the accent bar replaces type discrimination per D-03 (all teal for now).
   - Remove the 48x48 icon container — replaced by the accent bar.

**Verify:** `flutter test test/features/group_detail_screen_test.dart && flutter test test/features/events/event_command_center_test.dart` — stats grid widget is created; event card changes should not break event_command_center tests since personalBalance defaults to null (backward compatible).

### Task 03 — Rebuild GroupDetailScreen layout
**Wave:** 1 | **Reqs:** SCRN-01
**Input:** `GroupStatsGrid` widget (Task 02), updated `EventCard` (Task 02), existing `group_detail_screen.dart`
**Output:** Redesigned GroupDetailScreen with new above-the-fold layout, section reorder, settle-up CTA, skeleton loading

**Steps:**
1. Open `lib/features/groups/screens/group_detail_screen.dart` (609 lines). Perform these changes to `_buildContent`:
   - **Remove** the old `_buildStatsRow` call (member count + currency chips).
   - **Remove** the `GroupBalanceHero` and `GroupSpendingStats` widgets and their conditional rendering block (`if (hasExpensesData != null)`). Remove the imports for `group_balance_hero.dart` and `group_spending_stats.dart`.
   - **Add** import for `GroupStatsGrid` from `../widgets/group_stats_grid.dart`.
   - **Replace** the removed hero/stats area with the new above-the-fold content:
     ```
     GroupStatsGrid(
       userNetBalance: currentUserBalance?.netBalance ?? Decimal.zero,
       groupTotal: balancesData?.totalSpent ?? Decimal.zero,
       activeMembers: group.memberIds.length,
       eventCount: balancesData?.eventCount ?? 0,
       currency: group.currency,
     ),
     ```
   - **Add settle-up CTA** (D-10) below the stats grid: a full-width `SizedBox(height: AppColors.buttonHeight)` with `ElevatedButton` text "Settle Up", backgroundColor `AppColors.primary`, keyed with `GroupKeys.settleUpCta`. Wrap in a visibility condition: only show when `currentUserBalance?.netBalance != null && currentUserBalance!.netBalance != Decimal.zero`. onPressed navigates to `/group/$groupId/settle-up`.

2. **Reorder sections** per D-09:
   - Current order: `_buildMembersBalancesSection`, `_buildEventsSection`, `_buildInviteSection`, `_buildActivitySection`.
   - New order: `_buildEventsSection`, `_buildMembersBalancesSection`, `_buildInviteSection`, `_buildActivitySection`.
   - Simply swap the method calls in the Column children list.

3. **Update _buildEventsSection** to pass personal balance to EventCard:
   - In the `_buildEventsSection` method, access `balancesData` (from the parent scope or pass it as parameter). For each event, look up the current user's per-event balance: `final eventBalance = balancesData?.perEventBreakdown[currentUid]?[events[i].id];`
   - Pass `personalBalance: eventBalance` to each `EventCard`.
   - This requires making `_buildEventsSection` accept `balancesData` and `currentUid` as parameters, or lifting them to instance state.

4. **Replace `_buildLoading`** with skeleton composites:
   - Instead of `CircularProgressIndicator`, render a Column with `ModuleHeader(title: '', subtitle: '', useDarkTheme: true)` and then an Expanded SingleChildScrollView containing:
     - Stats grid skeleton: 2x2 grid of `SkeletonBlock` (surface bg, same aspect ratio as real stats grid)
     - CTA skeleton: Full-width `SkeletonBar` at 52dp height
     - Section skeletons: `SkeletonBar` for section headers, `SkeletonBlock` cards for event cards, `SkeletonCircle(40)` + `SkeletonBar` rows for member balances
   - Import `SkeletonLoader` from `lib/shared/widgets/skeleton_loader.dart`.

5. **File size check**: After changes, GroupDetailScreen should be ~450-500 lines (removed GroupBalanceHero/GroupSpendingStats widgets, extracted stats grid). If above 500 lines, ensure build methods are delegating to extracted widgets properly.

**Verify:** `flutter test test/features/group_detail_screen_test.dart` — all tests green including the new ones from Task 01. Then `flutter test` for full suite regression.
