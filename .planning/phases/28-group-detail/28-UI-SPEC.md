## Spacing Scale

All spacing from `AppSpacingTokens.standard` in `lib/core/theme/tokens/spacing_tokens.dart`.
Literal values that exactly match token values are acceptable in code (no forced refactor).

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| space4 | 4dp | Icon gaps, tight inline padding (stat card label-value gap) |
| space8 | 8dp | Compact internal padding (activity tile, chip padding) |
| space12 | 12dp | Card internal padding (stats cell, member card compact rows) |
| space16 | 16dp | Default section horizontal padding, element spacing |
| space20 | 20dp | Section header bottom margin, event card internal vertical padding |
| space24 | 24dp | Inter-section vertical gap (Stats → CTA, Events → Members, etc.) |
| space32 | 32dp | Bottom scroll padding (clear FAB overlap) |

Border radii (from same token file):

| Token | Value | Usage |
|-------|-------|-------|
| radiusSmall | 8dp | Chips, activity tiles |
| radiusMedium | 12dp | Buttons, settle-up CTA, stat card corners |
| radiusLarge | 16dp | Event cards, member balance cards, OpenContainer shape |

Button height: 52dp (`buttonHeight` token) — settle-up CTA, retry button.

Exceptions:
- FAB: 56dp diameter circle — Flutter's built-in `FloatingActionButton` default. Not a spacing token.
- Touch targets minimum: 48dp height for all tappable rows (activity tiles, member name rows, section "See all" links). Enforced via `InkWell` minimum tap area, not spacing tokens.
- Header safe area: `SafeArea` top padding applied inside `ModuleHeader` — not a spacing decision.

## Typography

Font: Plus Jakarta Sans throughout. All sizes from `AppTheme._buildTextTheme()` in `lib/core/theme/app_theme.dart`.

Exactly 4 sizes, exactly 2 weights. All supplementary roles map to one of these four slots.

| Role | TextTheme slot | Size | Weight | Line Height | Usage in this phase |
|------|----------------|------|--------|-------------|---------------------|
| Display | headlineLarge | 24sp | w600 | 1.2 | Group name in ModuleHeader |
| Heading | headlineSmall | 18sp | w600 | 1.2 | Section headers (Events, Members & Balances, Recent Activity) |
| Label | titleMedium | 15sp | w600 | 1.4 | Stat card labels, event card title, member name and net balance in balance card, settle-up CTA label |
| Body | bodyMedium | 14sp | w400 | 1.5 | Stat card values, header creation date, activity tile body text including timestamps, error state message, retry button label, event card date/type chip |

All supplementary text roles resolved:

| Usage | Resolved slot | Rationale |
|-------|---------------|-----------|
| Header subtitle (creation date) | bodyMedium 14sp w400 | Body slot — textSecondary color |
| Stat card value (amount) | bodyMedium 14sp w400 | Color-coded for YOUR BALANCE — weight distinguishes via color, not weight |
| Event card date/type chip | bodyMedium 14sp w400 | 2sp reduction from 12sp is imperceptible; textMuted color marks it as decorative |
| Member net balance amount | titleMedium 15sp w600 | Label slot — color-coded |
| Activity tile timestamp | bodyMedium 14sp w400 | Timestamps are decorative — textMuted color sufficient; w500 removed |
| Settle-up CTA label | titleMedium 15sp w600 | 1sp reduction from 16sp unnoticeable; w700 collapsed to w600 |
| Error state message | bodyMedium 14sp w400 | Body slot — textSecondary color |
| Retry button label | bodyMedium 14sp w400 | Body slot — textOnPrimary color on ElevatedButton |

Constraint: `textMuted` (#9CA3AF) is decorative only — never use for functional text, amounts, or interactive labels. WCAG AA fails at 2.86:1 on white. Timestamps and decorative chips only.

> Source: `lib/core/theme/app_theme.dart` `_buildTextTheme()` + CLAUDE.md WCAG note

## Screen States

This phase requires explicit contracts for all 4 states of the GroupDetailScreen:

### Loading State (D-11)

- Trigger: initial `groupDetailProvider` async value is `loading`
- Widget: `SkeletonLoader` (existing `lib/shared/widgets/skeleton_loader.dart`)
- Layout: full `Scaffold` with `ModuleHeader` shimmer at top, then content area skeleton
- Pattern: use `SkeletonLoader.groupList()` or `SkeletonLoader.eventCard()` variants already defined
- No `CircularProgressIndicator` — skeleton only

### Error State (D-12)

- Trigger: `groupDetailProvider` async value is `error`
- Widget: inline error — do NOT replace full screen
- Layout:
  1. `ModuleHeader` with title 'Group' (static — no data), subtitle '' (empty)
  2. `Expanded` centered column:
     - `Iconsax.warning_2` icon, 48dp, color `textMuted`
     - 16dp gap
     - Text: "Failed to load group" — `bodyMedium`, `textSecondary`
     - 16dp gap
     - `ElevatedButton` label "Try again" — calls `ref.invalidate(groupDetailProvider(groupId))`
- Header uses `useDarkTheme: true` to match normal loaded state

### Empty State — No Events (D-04, D-08)

- Trigger: `groupEventsProvider` returns an empty list
- Widget: `EmptyStateView` (existing `lib/shared/widgets/empty_state_view.dart`)
- Placement: inside the Events section, below the section header
- Copy: see Copywriting Contract below

### Empty State — No Activity

- Trigger: `groupActivityProvider` returns an empty list
- Widget: `EmptyStateView` without CTA
- Placement: inside the Recent Activity section

### Pull-to-Refresh (D-11)

- Widget: `RefreshIndicator` wrapping `SingleChildScrollView`
- Color: `primary` #0D7B74
- backgroundColor: `cardSurface` #F8F9FA
- `onRefresh`: invalidates `groupDetailProvider`, `groupEventsProvider`, `groupMembersProvider`, `groupActivityProvider`, `groupSettlementsProvider` (NOT `groupBalancesProvider` — it recomputes from streams automatically)
- Delay: 500ms after invalidation before completing

## Interaction Contracts

### FAB — Create Event (D-14)

- Icon: `Iconsax.add`
- Icon color: `textOnPrimary` #FFFFFF (BUG FIX — current code uses `Colors.black`)
- Background: `primary` #0D7B74
- Shape: `CircleBorder()`
- Semantics label: 'Create event'
- `onPressed`: `HapticService.lightImpact()` then `context.push('/group/$groupId/create-event')`
- Elevation: 8dp (from `floatingActionButtonTheme`)

### Settle-Up CTA (D-10)

- Visibility: only rendered when `currentUserBalance?.netBalance != Decimal.zero`
- Width: `double.infinity`
- Height: 52dp (`buttonHeight` token)
- Style: `DecoratedBox` with `primaryGradient` + `ElevatedButton` with transparent background
- Border radius: `radiusMedium` 12dp
- Label: "Settle Up" — titleMedium 15sp w600 `textOnPrimary`
- `onPressed`: `HapticService.mediumImpact()` then `context.push('/group/$groupId/settle-up')`
- Key: `GroupKeys.settleUpCta`

### Event Card Tap (D-15 — OpenContainer kept)

- Transition: `OpenContainer` from `animations` package
- `transitionType`: `ContainerTransitionType.fade`
- `transitionDuration`: 400ms
- `closedColor`: `Colors.transparent`
- `openColor`: `scaffoldBackground`
- `closedElevation`: 0, `openElevation`: 0
- `closedShape`: `RoundedRectangleBorder(borderRadius: BorderRadius.circular(radiusLarge))`
- `useRootNavigator`: false
- No haptic on card tap (OpenContainer handles its own gesture)

### Event Cards Entrance Animation (D-08)

- Widget: `FadeInList` wrapping event cards column
- Pattern: existing `lib/shared/animations/fade_in_list.dart`
- `FadeInList` replaces the bare `Column` in the events loop
- Placement: isolated from `groupBalancesProvider` watch scope to prevent animation replay on balance updates
- `disableAnimations`: respects Flutter's `MediaQuery.disableAnimations`

### Member Balance Card Accordion (D-09)

- Keep existing `AnimatedCrossFade` + `RotationTransition` expand animation
- Only restyle container: border radius `radiusLarge` 16dp, background `cardSurface`, expanded background `selectionFill`
- Expanded state: balance breakdown per event in compact rows
- Key: `GroupKeys.memberBalanceCard(memberId)` — existing keys, preserve

### Navigation Transitions (D-15)

| Route | Transition | Implementation |
|-------|------------|----------------|
| Event card → EventCommandCenter | ContainerTransform (OpenContainer) | Already correct — keep |
| Header settings icon → GroupSettingsScreen | slide-right (GoRouter default) | Keep |
| Settle-up CTA → GroupSettleUpScreen | slide-right (GoRouter) | Keep |
| "See all" activity → GroupActivityScreen | slide-right (GoRouter) | Keep |
| FAB → create-event picker | slide-up (GoRouter definition) | Keep per CLAUDE.md |

No transition changes. The existing mix is correct.

## Provider Rebuild Scope Contract

This section is part of the visual contract because rebuild scope directly affects animation behavior (RESEARCH.md Pitfall 2).

| Provider | Watch Location | Scope |
|----------|---------------|-------|
| `groupDetailProvider(groupId)` | `build()` root | Full scaffold rebuild on group name/date change (acceptable — rare) |
| `groupBalancesProvider(groupId)` | `Consumer` widget inside `_buildContent` | Isolates to stats grid + settle-up CTA only |
| `groupEventsProvider(groupId)` | `_buildEventsSection` only | Events section rebuild only |
| `groupMembersProvider(groupId)` | `_buildMembersBalancesSection` only | Members section rebuild only |
| `groupActivityProvider(groupId)` | `_buildActivitySection` only | Activity section rebuild only |
| `currentUserIdProvider` | `_buildContent` | Acceptable — provider never changes after auth init |

FadeInList for event cards must be inside `_buildEventsSection` (watches `groupEventsProvider`) and must NOT be inside any widget that watches `groupBalancesProvider`. This prevents animation replay on balance updates.
