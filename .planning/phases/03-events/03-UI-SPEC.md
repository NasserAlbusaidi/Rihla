# Phase 3 — UI Design Contract: Events

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Flutter + AppTheme) |
| Preset | not applicable |
| Component library | Flutter Material 3 (useMaterial3: true) |
| Icon library | Iconsax |
| Font | Plus Jakarta Sans (via google_fonts) |

**Note:** This is a Flutter app. No web-based design system (shadcn, Tailwind) applies. The canonical design system is `lib/core/theme/app_theme.dart` — all tokens sourced from there. All new components must import `AppColors` from that file and use no hard-coded values.

## Spacing Scale

Declared values from `AppColors` (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| space4 | 4dp | Icon gaps, inline text spacing, chip vertical padding |
| space8 | 8dp | Between list items, small row gaps, member count badge spacing |
| space12 | 12dp | Section subheading to content gap, button pair gap |
| space16 | 16dp | Card internal padding, form field to label gap, module card horizontal padding |
| space20 | 20dp | Scroll area between hero sections, input vertical padding |
| space24 | 24dp | Page horizontal padding, between major sections |
| space32 | 32dp | Top of scroll area, bottom of page content |

**Exception — touch targets:** All tappable icon-only controls (back button, settings icon, type picker close) must be exactly 44×44dp. This matches the existing `_LightBackButton` / `_DarkBackButton` in `ModuleHeader`. Do not reduce below 44dp regardless of visual icon size.

**Exception — FAB:** FloatingActionButton uses `CircleBorder` shape with system-default size (56dp). Position: `floatingActionButtonLocation: FloatingActionButtonLocation.endFloat`.

## Typography

All text uses Plus Jakarta Sans. The type scale is defined in `AppTheme._buildTextTheme`. The four roles this phase uses:

| Role | Size | Weight | Line Height | Flutter Style |
|------|------|--------|-------------|---------------|
| Body | 14sp | w500 | 1.5 | `bodyMedium` (color: textSecondary) |
| Label / Caption | 12sp | w700 | 1.4 | `labelMedium` (color: textSecondary) or `bodySmall` (color: textMuted) |
| Title | 16sp | w700 | 1.3 | `titleMedium` (color: textPrimary) |
| Heading | 28sp | w700 | 1.2 | `headlineLarge` (letterSpacing: -0.5, color: textPrimary or white on dark header) |

**Weights:** Exactly two weights are used across the entire phase. w500 is reserved for body text only (`bodyMedium`). w700 is used for all other roles: labels, captions, titles, headings, chip text, and badge text. No w600 or w800 anywhere.

**Event type picker card text:** Type name at 16sp w700 (titleMedium). Short description at 12sp w700 (bodySmall textMuted). Module chips at 12sp w700 (chip label style from chipTheme).

**Event card in timeline:** Event name at 16sp w700 (titleMedium, maxLines:1 overflow ellipsis). Meta row (date range, participant count, total) at 12sp w700 (textMuted).

**Event hub header:** Event name at 28sp w700 on dark gradient (headlineLarge white). Event type badge at 12sp w700 (white at 0.5 opacity, letterSpacing: 0.5). Group name subtitle at 12sp w700 (white at 0.5 opacity).

## Color

Sourced from `AppColors` in `lib/core/theme/app_theme.dart`:

| Role | Value | Token | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `#EFF2F7` | `AppColors.background` | Scaffold background, scroll area behind cards |
| Secondary (30%) | `#FFFFFF` | `AppColors.surface` / `surfaceCard` | All cards (event cards, type picker cards, form surface), module header light variant, bottom sheets |
| Accent (10%) | `#13EC92` | `AppColors.mint` / `primary` | See reserved list below |
| Destructive | `#EF4444` | `AppColors.rose` / `error` | Delete event confirmation dialog and error borders only |

**Dark gradient surfaces:** The event hub header (adapted ModuleHeader with `useDarkTheme: true`) uses `AppColors.darkHeaderGradient` (`#0F172A` → `#1E293B`). This is not an accent — it is a structural surface.

**Accent (mint `#13EC92`) reserved for:**
1. FAB background on GroupDetailScreen (the "Create Event" entry point)
2. FAB background on the adapted event hub (the "Add Expense" action)
3. Active/focused TextFormField border (2dp focused border)
4. `LoadingButton` gradient (primaryGradient: mint → `#0BAE6B`)
5. Selected module chip background in the Custom event module picker
6. Floating label color on focused input fields
7. TextButton foreground ("Done" link on bottom sheets)

**Accent is NOT used for:** event type icons (each type has a distinct semantic color — see Component Inventory), plain card borders, timeline section headers, or participant checkbox fill color.

**Semantic colors for event type icons** (these are module/type identity colors, not accent):
- Trip: `AppColors.mint` (`#13EC92`) — uses primary because Trip is the flagship type
- Camping: `AppColors.emerald` (`#10B981`) — outdoor/nature
- Travel: `AppColors.sky` (`#0EA5E9`) — movement/journey
- Night/Day Out: `AppColors.indigo` (`#6366F1`) — social/evening
- Custom: `AppColors.amber` (`#F59E0B`) — user-defined/flexible

**Dimming for past events:** Set container opacity to 0.6 (`withValues(alpha: 0.6)`) on the entire event card when the event's end date is before today. The card remains fully tappable.

## Component Inventory

New widgets this phase introduces. All reuse existing token values.

### EventTypePickerScreen (Step 1 of creation flow)

Full-screen scaffold with light `AppBar` (title: "Choose Event Type", leading: CloseButton). Scrollable vertical list of type cards — one card per type, not a grid.

**Type card anatomy:**
- Container: `AppColors.surface`, `borderRadius: AppColors.radiusLarge` (20dp), `boxShadow: AppColors.shadowRaised`, padding: 16dp all sides
- Left: 48×48dp icon container, `borderRadius: 14dp`, background: `typeColor.withValues(alpha: 0.1)`, icon size 24dp in `typeColor`
- Right: Column with type name (`titleMedium` 16sp w700), description (`bodySmall` 12sp w700 textMuted), then a horizontal Wrap of module chips
- Module chips: Chip with `AppColors.surfaceLight` background, `AppColors.radiusSmall` shape, 12sp w700 label, no border. Show only enabled modules for the type.
- Trailing: `Iconsax.arrow_right_3` at 18dp in `AppColors.textMuted`
- Inter-card spacing: 12dp (space12)

**Interaction:** Tap a card immediately advances to Step 2 (CreateEventScreen) with the selected type. No multi-select. Scale animation on press: 0.98 scale over 80ms using `_PressableWrapper` pattern from `SmartModuleCard`.

### CreateEventScreen (Step 2 of creation flow)

Full-screen scaffold with light `AppBar` (title: "New {EventType} Event", leading: BackButton that pops back to type picker).

**Form layout** (horizontal padding: space24):
- Top gap: space32
- Section label + space8 + field pattern from `CreateGroupScreen`

Fields in order:
1. "Event Name" label (`titleSmall`) + TextFormField (hint: "e.g. Summer camping trip")
2. space24
3. "Dates" label + Row of two DatePicker trigger buttons (start date, end date). Each button: OutlinedButton, `AppColors.radiusMedium`, full label "Select date" until set, then "Mar 30, 2026" format. Dates are optional.
4. space24
5. "Participants" label + checkbox list of group members (all pre-checked). Each row: 56dp height container, `Iconsax.user` avatar placeholder 32×32dp with `AppColors.surfaceLight` background, member name at `titleSmall`, checkbox on trailing. Selected state: no fill change on row — only checkbox is visually marked.
6. If Custom type: space24 + "Modules" label + module toggle rows (one per module). Toggle row: Row with module icon 24dp in semantic color, module name at `titleSmall`, Switch on trailing with active color `AppColors.primary`.
7. space48 (use literal 48dp — matches existing `CreateGroupScreen` pre-submit gap)
8. `LoadingButton` (label: "Create Event")
9. space32 bottom

**Validation:** Event name required. Show inline error under field using `errorBorder` style from InputDecorationTheme. At least one participant required — show SnackBar with error if all participants are deselected on submit.

### EventCard (timeline row in GroupDetailScreen)

Container: `AppColors.surface`, `borderRadius: AppColors.radiusLarge`, `boxShadow: AppColors.shadowRaised`, padding: space16 all sides.

**Anatomy:**
- Row: [48×48dp type icon container] [space12] [Expanded column] [space8] [`Iconsax.arrow_right_3` 18dp textMuted]
- Icon container: `borderRadius: 14dp`, background: `typeColor.withValues(alpha: 0.1)`, icon 22dp in `typeColor`
- Column:
  - Row: event name (16sp w700 textPrimary, maxLines:1 overflow ellipsis) + space4 + type badge chip (12sp w700, `typeColor`, `typeColor.withValues(alpha:0.1)` background, radiusSmall)
  - space4
  - Meta row: [date range or "No dates"] [·] [participant count + " people"] — 12sp w700 textMuted
  - space4
  - Total spent: "0.000 OMR" (or actual amount in Phase 5) — 12sp w700 textSecondary

**Past event dimming:** Wrap the entire card in `Opacity(opacity: 0.6)` when `event.isPast == true`.

**Inter-card spacing:** 12dp (space12) between cards in the list.

### Events Section in GroupDetailScreen

Replaces the current `_buildEventsSection` placeholder.

Section header: Row with "Events" text (`titleMedium` 16sp w700) + Spacer + count chip ("{N}" in a surfaceLight pill, 12sp w700 textSecondary, radiusSmall, horizontal padding: space8, vertical: space4).

Below header: space12 gap, then the event card list. Each card separated by space12.

Empty state: `EmptyStateView(icon: Iconsax.calendar_add, title: "No events yet", message: "Tap the + button to create the first event for this group.")`. No action button on EmptyStateView — the FAB is the affordance.

FAB: Add `floatingActionButton: FloatingActionButton(...)` to `GroupDetailScreen`'s Scaffold. Icon: `Iconsax.add`. Color: `AppColors.primary`. Shape: `CircleBorder()`. On tap: `Navigator.push(AppPageRoute(builder: (_) => EventTypePickerScreen(groupId: groupId)))`.

### Adapted Event Hub (EventCommandCenter)

Structurally identical to existing `CommandCenter`. Replace `TripHeader` with `ModuleHeader(useDarkTheme: true)`:
- `title`: event.name (28sp w700 white)
- `subtitle`: "${eventTypeLabel(event.type)} · ${group.name}" (12sp w700 white 0.5 opacity)
- `actions`: `[IconButton(icon: Iconsax.more_circle)]` for future edit/delete access

Module cards use existing `SmartModuleCard`. Cards are rendered only for modules enabled in `event.modules`. Module color mapping:
- Ledger: `AppColors.emerald`
- Gear: `AppColors.amber`
- Logistics: `AppColors.sky`
- Vault: `AppColors.indigo`
- Memories: `AppColors.mint`

FAB: `Iconsax.add` on `AppColors.primary` CircleBorder — opens Add Expense (same as existing CommandCenter).

### Delete Event Confirmation Dialog

`AlertDialog` with:
- title: "Delete event?" (16sp w700 textPrimary)
- content: "This will permanently remove {event.name} and cannot be undone. Financial records are preserved." (14sp w500 textSecondary)
- actions: [TextButton("Cancel", `AppColors.textSecondary`), ElevatedButton("Delete Event", `AppColors.error` background)]

## Interaction Contracts

### Event Creation Flow

1. Tap FAB on GroupDetailScreen
2. `EventTypePickerScreen` slides in via `AppPageRoute` (slide-right)
3. Tap a type card — `CreateEventScreen` slides in via `AppPageRoute`
4. Fill form, tap "Create Event"
5. `LoadingButton` enters loading state (spinner). No navigation yet.
6. On success: pop both screens (use `Navigator.popUntil`) and navigate to `EventCommandCenter` via `Navigator.push(AppPageRoute(...))`
7. On error: `LoadingButton` returns to idle, `SnackBar` with error message slides up

### Pull-to-Refresh (Phase 2 Gap #8)

`RefreshIndicator` wraps the `SingleChildScrollView` in `HomeScreen` groups list. `onRefresh` calls `ref.invalidate(userGroupsProvider)`. Color: `AppColors.primary`.

### Module Toggle (Custom Event)

Each module toggle in `CreateEventScreen`:
- `Switch` with `activeColor: AppColors.primary`
- Row height: 56dp
- Disabled state (Ledger is always on): `Switch.value = true`, `onChanged: null`, opacity 0.5 on the row

### Past Event Dimming

Derived from event dates using the same logic as `Trip.isPast` in the existing trip model. No explicit state field. Opacity wraps the full card widget tree, not just the icon.

### Optimistic Event Creation (Offline)

When event is created while offline, the card appears immediately in the timeline at the top of the list. A small `OfflineBanner` (existing shared widget) is visible above the list. The card shows no "syncing" indicator — Firestore offline persistence handles this transparently.

## Animation Contract

| Trigger | Animation | Duration | Curve |
|---------|-----------|----------|-------|
| Screen entry (AppPageRoute) | Slide from right | 300ms | easeInOut (existing AppPageRoute default) |
| Card press (type picker, event card) | Scale 1.0 → 0.98 | 80ms | easeInOut (matches _PressableWrapper) |
| EventTypePickerScreen list items | fadeIn + slideY(begin: 0.05) per item, staggered 40ms | 400ms | easeOutCubic (matches CommandCenter animate pattern) |
| EmptyStateView | fadeIn + scale(0.95 → 1.0) | 400ms | default (existing EmptyStateView behavior) |
| LoadingButton transition | Instant swap to CircularProgressIndicator 24×24dp, strokeWidth: 2.5 | — | — |

Respect `MediaQuery.of(context).disableAnimations` — all animations must be skipped when this flag is true (existing EmptyStateView already does this; apply same guard to staggered list animations).

## Accessibility Contract

- All tappable elements have `Semantics(button: true)` and a meaningful `label`. Use `Semantics(label: 'Create event', button: true)` on the FAB.
- Event type cards: `Semantics(label: '{type name}: {description}. Modules: {module list}', button: true)`
- Participant checkbox rows: `Semantics(label: '{member name}', checked: isSelected)`
- Delete button in dialog: `Semantics(label: 'Delete event permanently', button: true)`
- Event hub options button: `Semantics(label: 'Event options', button: true)` wrapping the `IconButton(icon: Iconsax.more_circle)` in the event hub header actions.
- Minimum touch target: 44×44dp enforced on all interactive elements (back buttons, icon buttons, FAB, event cards)
- Color contrast: All text on `AppColors.background` or `AppColors.surface` uses `textPrimary` (#0F172A on #FFFFFF = 19.1:1 ratio). `textSecondary` (#475569 on white = 5.9:1 ratio, passes AA). `textMuted` (#94A3B8) is used only for non-essential decorative text (dates, meta), not for required information.
