## Spacing Scale

All spacing follows the `AppColors` token scale defined in `lib/core/theme/app_theme.dart`. These values are already declared as constants; use them directly, not raw numbers.

| Token | Value | AppColors constant | Usage |
|-------|-------|--------------------|-------|
| xs | 4dp | `AppColors.space4` | Icon gaps, tight inline padding |
| sm | 8dp | `AppColors.space8` | Compact row spacing, chip padding |
| md-12 | 12dp | `AppColors.space12` | Internal widget padding |
| md | 16dp | `AppColors.space16` | Default element spacing, list item padding |
| lg-20 | 20dp | `AppColors.space20` | Field vertical padding, section sub-gaps |
| lg | 24dp | `AppColors.space24` | Section padding, screen horizontal inset |
| xl | 32dp | `AppColors.space32` | Layout section gaps |

Exceptions:
- Bottom sheets use `EdgeInsets.fromLTRB(24, 24, 24, 40)` — the 40dp bottom accounts for system nav bar clearance. This is an established pattern in `logistics_screen.dart` and must not be changed.
- Touch targets for interactive controls (snackbar actions, remove-member buttons) must meet the 44dp minimum, enforced by Flutter's `MaterialTapTargetSize.padded` default.
- SubgroupCard border radius: `BorderRadius.circular(32)` for the bottom sheet container — this is the existing pattern, not a deviation.

## Component Inventory

These are the specific UI surfaces touched by Phase 12. No new components. Each fix area is a surgical change to existing widgets.

### Fix Area 1: _tripCurrency Getter (add_expense_screen.dart + edit_expense_sheet.dart)

- **Component type:** Invisible derived value — no rendered widget change
- **Before state:** Reads from dead `userTripsProvider` → always returns 'OMR'
- **After state:** Reads from `event.currency` via `ref.read(eventDetailProvider(...)).valueOrNull?.currency ?? 'OMR'`
- **Visible change:** None during normal load. When event has a non-OMR currency, the currency label shown in the decimal-precision calculator and the expense submit payload will reflect the actual currency. This is the desired outcome.
- **Loading fallback:** `?? 'OMR'` — same as before. No spinner, no empty state.

### Fix Area 2: _PayerSelector visibility (split_scope_selector.dart + edit_expense_sheet.dart)

- **Component type:** `_PayerSelector` — a `Column` with a dropdown inside `add_expense_screen.dart` and `edit_expense_sheet.dart`
- **Before state:** `isLeader` always false (dead provider) → selector always hidden
- **After state:** `isLeader = event.createdBy == currentUid` → selector visible to event creator, hidden to others
- **Visible change:** The "PAID BY" dropdown row becomes visible for the event creator. It was previously invisible for everyone. No layout changes — the widget already exists, only its visibility condition changes.
- **Empty / loading:** If `currentUid` is null (Firebase auth not yet loaded), `isLeader` evaluates false. Dropdown stays hidden. Acceptable — same behaviour as loading state.

### Fix Area 3: Logistics Write Stubs (logistics_screen.dart — 6 stubs)

- **Component type:** Callbacks passed to `SubgroupCard` widget + `_showMemberPicker` + `_showCreateDialog`
- **Before state:** `debugPrint` — no-op
- **After state:** Each callback calls the corresponding `SubGroupService` method. On failure: `ScaffoldMessenger.showSnackBar` with error message. Auto-dismiss (no action button).
- **Visible change on success:** Firestore listener updates `eventSubGroupsProvider` → `ListView.builder` re-renders with new data. No explicit loading indicator.
- **Visible change on failure:** Snackbar appears from bottom: dark pill (`AppColors.textPrimary` background), white 14sp w500 text, `SnackBarBehavior.floating`, `BorderRadius.circular(16)` — all from `snackBarTheme`. Message is plain text: no icons, no action label, no retry.

## Interaction Patterns

### Snackbar error pattern (canonical — from Phase 11)

```dart
try {
  await ref.read(subGroupServiceProvider).methodName(...);
} catch (e) {
  if (mounted) {
    ScaffoldMessenger.of(context).showSnackBar(
      const SnackBar(content: Text("Couldn't [verb] [noun] — try again")),
    );
  }
}
```

- No `duration` override — use the default (4 seconds).
- No `action` parameter — no retry button.
- `mounted` guard is mandatory — all logistics write calls are async and the widget may dispose.
- Use em dash (`\u2014`) between the problem description and the hint, matching gear_screen.dart precedent: `"Couldn't update priority \u2014 try again"`.

### Member picker addMember context safety

The `_showMemberPicker` opens a `showModalBottomSheet` containing a `Consumer`. The inner context belongs to the sheet's route, which is popped before the service call completes. Pattern:

1. Pop the sheet: `Navigator.pop(context)` — executes synchronously inside the tap handler.
2. Call the service using a callback passed to `_showMemberPicker` that captures the outer screen's `ref` and `context` (both valid on the outer `_LogisticsScreenState`).
3. Show snackbar via `if (mounted) ScaffoldMessenger.of(context)` using the outer context.

This avoids "Looking up a deactivated widget's ancestor" errors (Research Pitfall 2).

### isLeader evaluation

```dart
final currentUid = ref.watch(currentUserProvider)?.uid;
final isLeader = currentUid != null && event.createdBy == currentUid;
```

If `currentUid` is null: `isLeader` is false. Payer selector stays hidden. No loading spinner — the loading state is indistinguishable from "not a leader" visually, which is acceptable.

## State Transitions

| State | Visual |
|-------|--------|
| Normal / loaded | Existing screen layout; payer selector visible for creator only |
| Write in progress | No optimistic update, no spinner — Firestore offline queue handles persistence |
| Write failed | Snackbar appears at bottom, auto-dismisses after 4s |
| Event currency non-OMR | Currency label in expense form reflects actual currency |
| Event currency loading | Falls back to 'OMR' via `?? 'OMR'` — no visible spinner |
