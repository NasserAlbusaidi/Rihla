### File 1: `profile_notifications_section.dart`

Create a `ConsumerWidget` named `ProfileNotificationsSection`.

**Section header:** icon `Iconsax.notification`, label `'NOTIFICATIONS'` — same pattern as `ProfileStatsSection`'s header (icon size 16, `textSecondary`, fontSize 11, fontWeight w600, letterSpacing 1.5).

**Notification tile (per D-05 through D-08):**
- Wrapped in a `Container` with `cardSurface` background, `BorderRadius.circular(16)`, `shadowRaised` shadow (matching stats card style).
- Left side: 36px icon container (`inputFill` bg, `borderRadius: 10`, `Iconsax.notification` icon size 18, `textSecondary` color).
- Title: `'Push Notifications'` in `fontSize: 14`, `fontWeight: FontWeight.w500`, `textPrimary`.
- Right side: `Switch.adaptive` widget with key `ProfileKeys.notificationSwitch`.
- Key on the outer tile: `ProfileKeys.notificationToggleTile`.

**Toggle state logic** (three states based on providers — per D-05 through D-08):

Read `ref.watch(settingsProvider).pushNotificationsEnabled` and `ref.watch(notificationStatusProvider)`.

1. **`pushNotificationsEnabled == true` AND status != `permissionDenied`:** Switch is ON, enabled. `onChanged` calls `ref.read(settingsProvider.notifier).setPushNotificationsEnabled(false)` + `HapticService.selection()`.

2. **`pushNotificationsEnabled == false` AND status != `permissionDenied`:** Switch is OFF, enabled. `onChanged` calls `ref.read(settingsProvider.notifier).setPushNotificationsEnabled(true)` + `HapticService.selection()`. The `appBootstrapProvider` will react and call `NotificationService.initialize()`, which triggers the OS permission dialog. If the OS denies, bootstrap sets `pushNotificationsEnabled` back to false.

3. **`status == permissionDenied`:** Switch is OFF, disabled (`onChanged: null`). Show subtitle text `'Enable in device Settings'` in `fontSize: 12`, `textSecondary` color. Wrap the entire tile in a `GestureDetector` with `onTap` that calls `AppSettings.openAppSettings()` (from `app_settings` package). Import: `import 'package:app_settings/app_settings.dart';`

**CRITICAL per Pitfall 1:** Do NOT call `NotificationService.initialize()` directly from the widget. Only call `settingsProvider.setPushNotificationsEnabled(value)`. The `appBootstrapProvider` handles the FCM side.

**Permission hydration (per Pitfall 2):** Add a one-time check in the `build` method using `ref.listen` (or a `useEffect`-style pattern): on first build, call `FirebaseMessaging.instance.getNotificationSettings()` and if `authorizationStatus == AuthorizationStatus.denied`, update `ref.read(notificationStatusProvider.notifier).state = NotificationStatus.permissionDenied`. Wrap in try/catch. Import `firebase_messaging`.

Switch active color: `AppColorTokens.light.primary`. Switch track color when off: `AppColorTokens.light.inputFill`.

final metadata = ref.read(appMetadataProvider).valueOrNull ?? AppMetadata.fallback();
final uri = Uri(

}
