## Copywriting Contract

Phase 8 introduces one new text pattern (the event label) and clarifies fallback strings for existing elements.

| Element | Copy |
|---------|------|
| Event label format (happy path) | `"{Event Name} — {Mon DD}"` e.g. `"Camping Weekend — Mar 15"` |
| Event label format (truncated) | `"{First 27 chars}... — {Mon DD}"` e.g. `"Annual Summer Road Trip to ... — Jun 3"` |
| Event label fallback (name missing) | `"{EventType display name} — {Mon DD}"` e.g. `"Camping — Mar 15"` |
| Event label fallback (date missing) | `"{Event Name}"` with no date segment — omit em dash entirely |
| Participant picker empty state (Fix #1 — before fix, shown to users) | `"No participants available"` (existing copy, confirmed in split_scope_selector.dart) |
| Participant picker after fix | Shows actual participant names — no empty state visible in normal flow |
| Column comment (Fix #3 — code only, not user-facing) | See RESEARCH.md code examples section |
| Primary CTA on settle-up screen | `"Confirm Settlement"` (existing — no change) |
| Settle-up screen section heading | `"Per Event Breakdown"` (existing — Fix #2 changes content, not the heading) |

No destructive actions are introduced or changed in Phase 8.

Fallback chain for event label (D-02):
1. `event.name` if present and `event.startDate ?? event.createdAt` is present
2. `event.type.displayName` if event name is missing
3. Should never reach a third fallback given model constraints (Event always has type)

Source: CONTEXT.md D-01, D-02, D-04; RESEARCH.md code examples

## Component Inventory

Phase 8 modifies existing components only. No new widgets are created.

### Modified: `group_settle_up_screen.dart`

| Change | Before | After |
|--------|--------|-------|
| `_shortEventLabel(eventId)` | Returns `"Event …{last6}"` truncated eventId | Replaced by `_buildEventLabel(eventId, eventMap)` using event name + date |
| Data source for event labels | None (string manipulation on eventId) | `groupEventsProvider(widget.groupId).valueOrNull` watched in `build()` |
| Per-event row layout | Single text line (eventId label) | Two-part text: name at 14sp w700 + date at 12sp w500 muted |

Visual specification for the per-event breakdown row (two-part label):
```
[settlement amount]   [event name w700 textPrimary] [" — " + date w500 textMuted]
```
Both text segments are on the same line. Use `RichText` with two `TextSpan` nodes, or two `Text` widgets in a `Row` with `mainAxisSize: MainAxisSize.min`. The event name segment uses `overflow: TextOverflow.ellipsis` with a max width computed relative to available row width — the truncation at 30 chars is applied in the string builder, not via Flutter overflow.

### Modified: `split_scope_selector.dart`

| Change | Before | After |
|--------|--------|-------|
| Participant data source | `tripLogisticsParticipantsProvider(tripId)` (StreamProvider, reads SQLite) | `eventLogisticsParticipantsProvider(event)` (Provider, derives from Event object) |
| Constructor param | `tripId: String` | `event: Event` |
| Empty state visibility | Shown for all Firestore-only events | Never shown for valid events (participants from Event model) |

No visual change to the participant chips — the existing chip styling (`AppColors.primaryLight` / `AppColors.surfaceLight`) is correct and unchanged.

### Modified: `add_expense_screen.dart` and `edit_expense_sheet.dart`

Pass `Event` object to `SplitScopeSelector` instead of `tripId` string. If `Event` is not yet available (loading state), render `SplitScopeSelector` with an empty list and a `CircularProgressIndicator` in the custom section until the event loads. Use existing `AppColors.primary` for the progress indicator color.

### Modified: `balance_cache_repository.dart` and `cache_service.dart`

Comment-only changes. No visual impact. No UI review required for Fix #3.

### New method: `AppFormatters.formatShortMonthDay(DateTime)`

Returns `"Mar 15"` format (3-letter month abbreviation + space + day number, no leading zero, no year). Used exclusively in the event label builder in `group_settle_up_screen.dart`.

## Interaction Contracts

### Fix #2: Per-event breakdown labels

- Labels are static text — no tap, no navigation (D-03)
- Loading state: while `groupEventsProvider` is loading, render fallback labels (event type) per D-02. Do not show a spinner inside the breakdown row.
- Rebuild behavior: when `groupEventsProvider` emits data after loading, `ref.watch` triggers rebuild and real labels replace fallback labels — standard Riverpod behavior, no special handling needed

### Fix #1: Custom split participant list

- Loading state: if `eventDetailProvider` has not resolved when the expense screen opens, show `CircularProgressIndicator` (size 20, color `AppColors.primary`) in place of the participant selector
- Error state: if `eventDetailProvider` emits an error, show the inline error text `"Could not load participants. Try reopening this screen."` at 12sp, w500, `AppColors.error`
- Normal state: participant chips render immediately from the Event object (synchronous `Provider.family`, no async wait)

### Fix #3: Column naming

No interaction contract — code-comment-only change.
