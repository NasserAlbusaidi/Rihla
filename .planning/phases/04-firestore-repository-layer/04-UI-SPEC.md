# Phase 4 — UI Design Contract

> Visual and interaction contract for Phase 4: Firestore Repository Layer.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Phase UI Scope

Phase 4 is a backend migration phase. It introduces **no new screens and no new navigation routes**. All per-event module write paths are rewired from Supabase to Firestore. The surface-level UI interaction contract covers three concerns:

1. **Offline write feedback** — the `OfflineBanner` already handles the global offline state signal. No new widget is needed; the existing banner text is confirmed correct for this phase.
2. **Lazy migration loading state** — when a user opens a pre-migration event and Firestore subcollection data is being back-filled from Supabase, the module screen must show a loading state while migration runs.
3. **Migration error recovery** — if lazy migration fails (Supabase unreachable), the module screen shows an error state with a retry affordance.

Everything else in this phase is internal wiring. The design contract specifies tokens, copy, and states for the three concerns above. All other visual properties are **carry-forward from the existing design system** (`app_theme.dart`) and are documented here for executor reference.

## Interaction States

Phase 4 introduces three new interaction states. Each is specified below with exact copy and visual treatment.

### State 1: Lazy Migration In Progress

**Trigger:** User opens an event module screen (e.g. Ledger, Gear) for the first time after Phase 4 deploys. The event has a `bridgeTripId` and the Firestore subcollection is empty. `LazyMigrationService` is running.

**Visual treatment:**
- Replace the module's normal list content with `SkeletonLoader` items (use existing `SkeletonLoader` widget).
- Show a text label above the skeleton: "Syncing your data..." at 12sp, w600, `AppColors.textMuted`.
- No progress bar, no percentage — migration is fast and the indeterminate state is sufficient.
- `OfflineBanner` is visible if offline (migration cannot proceed offline — see State 3).

**Duration:** Show for the duration of the lazy migration fetch. Dismiss immediately when first Firestore snapshot emits data.

**Transition:** Fade in the content list from opacity 0 to 1 over 300ms (`Curves.easeOut`) when migration completes and data arrives.

### State 2: Migration Complete / Module Data Loaded

This is the normal module operating state post-migration. No new visual treatment. Existing module screens render as before, now sourcing data from Firestore snapshots instead of SQLite streams. No user-visible difference.

### State 3: Migration Error (Supabase Unreachable During Lazy Migration)

**Trigger:** `LazyMigrationService` catches an exception when attempting to fetch from Supabase via `bridgeTripId`. The user is on the module screen.

**Visual treatment:**
- Replace skeleton with `EmptyStateView` using:
  - Icon: `Icons.sync_problem_rounded`
  - Icon color: `AppColors.error`
  - Title: see Copywriting Contract below
  - Message: see Copywriting Contract below
  - Action button: "Try Again" label, triggers retry of lazy migration
- `EmptyStateView` `actionLabel` = "Try Again", `onAction` = retry callback.

**Recovery:** On retry tap, show `SkeletonLoader` again (State 1) and re-attempt migration.
