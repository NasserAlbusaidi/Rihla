<objective>
Migrate every widget in `lib/shared/widgets/` (13 files) + `lib/core/theme/error_widgets.dart` + `lib/core/router/app_router.dart` transition shells from direct `AppColorTokens.light.*` reads to `context.colors.*`. These widgets propagate to every feature, so Wave 3 inherits a correctly-themed shared-widget layer.

Per D-03 this is mechanical `s/AppColorTokens\.light\.(\w+)/context.colors.$1/g` replacement with three knock-on edits per file:
1. Add `BuildContext` access to helper functions if they consume colors statelessly
2. Remove `const` from widget constructors that reference tokens (they can no longer be const)
3. Per D-11: textMuted triage — functional text → textSecondary; decorative → keep textMuted with justification comment

Per D-20: opportunistic spacing token adoption on the SAME files.

Purpose: Without Wave 2, Wave 3's feature migration would inherit light-hardcoded shared widgets, silently breaking dark mode at every feature screen.
Output: Shared-widget layer fully theme-aware; test suite confirms no render regressions.
</objective>

<interfaces>
Established in Plan 01:
- `context.colors` extension resolves AppColorTokens from Theme.of(context).extension<AppColorTokens>()!
- Both AppTheme.lightTheme and AppTheme.darkTheme register the extension — the extension never returns null.
- `context.spacing.space4/space8/space12/space16/space20/space24/space32` is the spacing token API.

Substitution rule (mechanical):
```
s/AppColorTokens\.light\.(\w+)/context.colors.$1/g
s/const EdgeInsets\.all\(16\)/EdgeInsets.all(context.spacing.space16)/g  # only if widget has BuildContext
```

textMuted triage rule (per D-11):
```
Is this text read as information (label/amount/hint/body)?
  YES → context.colors.textSecondary
  NO (pure decorative: •, faint chevron, divider glyph) → keep context.colors.textMuted + // textMuted-decorative-justified: <reason>
```

Apply to each file under `lib/shared/widgets/` (13 files total — list in files_modified):

**Step 1 — Color migration (mechanical):**
Replace every `AppColorTokens.light.<name>` → `context.colors.<name>`. If a helper method that doesn't have BuildContext references tokens, refactor it to accept `BuildContext` OR `AppColorTokens` as a parameter. Do NOT fall back to `AppColorTokens.light` as a "default" — that defeats the migration.

**Step 2 — `const` constructor removal:**
Any widget constructor that embeds a color reference can no longer be `const`. Remove `const` keyword from the constructor call site AND any `const` annotation at the field level that chains to the color.

**Step 3 — textMuted triage (per D-11):**
For every `context.colors.textMuted` reference:
- If it's labels, amounts, body copy, hints, or accessibility labels → replace with `context.colors.textSecondary`.
- If it's a decorative separator (`•`), faint chevron in inactive state, divider glyph, or placeholder icon tint → keep `textMuted` BUT add `// textMuted-decorative-justified: <element description>` on the line directly above.
- When unclear → bias toward `textSecondary` (accessibility wins).

Current textMuted count in shared widgets (to decide per-file): 0 in most, but check each file.

**Step 4 — Spacing tokens (opportunistic per D-20):**
On ONLY the files you're already touching, if a numeric value in `EdgeInsets.all(N)`, `EdgeInsets.symmetric(horizontal: N, vertical: N)`, `SizedBox(height: N)`, `SizedBox(width: N)`, or `Padding(padding: EdgeInsets.all(N))` matches the standard token set `{4, 8, 12, 16, 20, 24, 32}`, replace with `context.spacing.spaceN`. Odd values (6, 10, 14, 18, 26) stay numeric — do NOT round.

Example:
```dart
// Before:
const Padding(padding: EdgeInsets.all(16), child: Text(...))
// After (widget no longer const):
Padding(padding: EdgeInsets.all(context.spacing.space16), child: Text(...))
```

**Step 5 — Import cleanup:**
If a file's only use of `AppColorTokens` was direct `.light.*` reads (now replaced), remove the `import '.../color_tokens.dart'` line. `context.colors` comes from `domain_aliases.dart` which itself comes through `app_theme.dart` transitively; add `import 'package:safar/core/theme/tokens/domain_aliases.dart';` only if the context extension isn't already reachable (it should be in most cases via `app_theme.dart`).
