**5. Golden harness Builder pattern (test/goldens/golden_harness.dart)**
Current (lines 143-150 and 200-206) — reads a static alias inside build():
```dart

  return Container(
    ...
    boxShadow: AppShadowTokens.standard.raised,  // STATIC — does not flip
```

The `context` passed into `_buildHeroCard` / `_buildRowsCard` is the harness widget's own BuildContext, which IS under the theme — so `context.shadows.raised` will work directly without a Builder. Verify by inspecting the call chain: `build() → _buildHeroCard(context)` where `context` is the `StatelessWidget.build` context, already under `MaterialApp.theme`. NO Builder wrapping is strictly required if `context` is already theme-scoped. BUT the VERIFICATION.md recommends "through a Builder" for defensive correctness against future refactors that might move these calls behind a Theme override. A Builder is a 3-line addition that costs nothing and survives refactors. Use it.

Pattern:
```dart
Widget _buildHeroCard(BuildContext context) {
  return Builder(
    builder: (context) => Container(
      ...
      boxShadow: context.shadows.raised,
    ),
  );
}
```
