**Bug 1 — Split rounding (CRITICAL).** Two locations have the same bug:

1. `expense_provider.dart` line ~274: The `perHead` calculation truncates via `scaleOnInfinitePrecision: 3`. Fix: after computing `perHead`, calculate `remainder = expense.amount - (perHead * Decimal.fromInt(splitCount))`. When iterating `splitRecipients`, add `perHead` to all recipients except the last one — add `perHead + remainder` to the last recipient. Use an indexed iteration or track the last element.

2. `ledger_screen.dart` line ~281: Same pattern — `share` is truncated. Fix identically: compute `remainder = expense.amount - (share * Decimal.fromInt(splitCount))`. When the current participant is the LAST in the split list, their share is `share + remainder`. Pick a deterministic "last" — sort splitIds alphabetically so the remainder assignment is stable. If splitIds is null (global scope), sort `participants` by id.

**Bug 2 — Wrong balance user (CRITICAL).** `ledger_screen.dart` line ~129: Replace `participants.isNotEmpty ? participants.first.id : null` with a lookup using Firebase auth UID. The build method has access to `ref` (it's a ConsumerWidget). Use: `final uid = ref.read(currentUserProvider)?.uid;` then `final currentParticipantId = participants.where((p) => p.userId == uid).firstOrNull?.id;` — fall back to `participants.firstOrNull?.id` if no match (defensive). Import `currentUserProvider` from auth providers.

**Bug 7 — Hardcoded currency (partial).** `expense_model.dart` line ~196: The `String get currency => 'OMR'` getter ignores Firestore data. The `Expense` class constructor already has fields parsed in `fromFirestore` — check if a `_currency` field exists. If not: add a `final String currency` field to the constructor (default `'OMR'`), set it from `data['currency']` in `fromFirestore` (line ~135 already reads `currency` into a local but only uses it for MoneySerializer). Wire that local into the constructor. Remove the hardcoded getter. Update `copyWith` if it exists. Do NOT touch other files' hardcoded 'OMR' strings in this task — those are fallback defaults for when no currency is available and are acceptable.
