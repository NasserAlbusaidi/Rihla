Cheapest leverage

  1. Add accessible names to the amount field and core icon buttons. This removes the only current would-quit finding and likely moves Accessibility from 78 into the low/mid-80s.
  2. Wrap group identity edits in the same bounded write contract as money writes. This closes the lingering offline spinner/write-contract exception in the groups surface.
  3. Make the release QA gate honest and commit-scoped. The app can keep shipping, but this is still the governance drag keeping CI/CD below B+.

What carries the score

  • Server-authoritative security model and deep emulator/rules coverage.
  • Better first-hour/offline integrity after the atomic group founding batch.
  • Core money UI no longer lies about equal-split rounding and no longer opens blank Exact/Percent editors.

What drags it

  • The central amount input still has no accessible name.
  • Arabic copy/plural polish remains below the rest of the app's infrastructure quality.
  • Golden visual coverage is still not a real CI protection layer.
  • The sign-out pending-write copy/window and group edit offline write path still need hardening.
  • Two-device physical QA is still deferred despite release automation being strong.

Judge summary

Rihla moved from 86.61 to 88.45 because the latest run closed three highly visible trust and correctness defects: equal split preview, Exact/Percent seeding, and weighted zero-share remainder. The core app now feels much closer to its architecture quality. The reason it is still B+ rather than A- is no longer money truth; it is access, governance, and a handful of stale engineering surfaces. One abandonment-plausible finding remains: the central amount field is still unlabeled for assistive tech. Fix that, then tighten the group edit offline write and release QA gate, and the next honest score should be in A- range.
