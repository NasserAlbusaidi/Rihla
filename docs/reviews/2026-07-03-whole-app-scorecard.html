What carries the score

  • Money engine, byte-for-byte: client BalanceCalculator ↔ TS recomputeNet mirror — matching ROUND_DOWN truncation, negative-owed guard fires first both sides, per-currency bucketing, exact decompose, #596 regression-pinned.
  • Server-authoritative security with teeth: App Check on every callable (one documented GDPR exception), per-currency net-zero deletion gates, a claim/merge impersonation seal, 211 rules-emulator assertions.
  • Data-loss-critical auth is correct: #213 restored-session-KEPT never re-mints a UID; the #647/#648 swap gate resolves UID first, then groups, through all three entry points — never re-gated on CTA visibility.
  • Disciplined #412 offline handling: one bounded-race helper applied uniformly at every money write; connectivity event-driven from SDK metadata; offline traps tested with real never-completing Completers.
  • Test rigor where the money is: byte-differential oracle parity across identity/money/currency axes, complete Functions coverage, and a SHA-bound deploy ceremony verified in sync with prod (backend-deployed=abee70e8, zero pending delta).

What drags it

  • Silent money loss on failed replay: onLateError unwired everywhere — a rejected queued write vanishes with only a background Sentry event. Highest-leverage fix.
  • Raw Firebase text leaks on the core expense add/edit/delete flow, bypassing the app’s own friendly-error translator.
  • Ledger money invisible to screen readers — RAmount has no Semantics; amounts render currency-less; sign is glyph + colour only.
  • Maintainability debt on the riskiest code: 15 files exceed the 800-line cap (to ~2.4×, in expense-entry/settle-up/profile) and events/ledger/groups form a bidirectional import cycle.
  • Convention-dependent hardening: PII protection is convention-only (no central beforeSend scrubber), asymmetric date read-fence, and an un-gated bare firebase deploy beside the full ceremony.

How this grade was produced

Identical rubric, weights, and method to the first whole-app grade — re-run against the new HEAD. 16 blind, fresh-context expert reviewers (one per weighted category, zero session history) read the code and graded 0–100 against a shared anchor; every critical/major finding was handed to an independent skeptic prompted to refute it against live code; only survivors reached the Opus judge, which calibrated each category and computed the weighted composite. The composite was independently recomputed by hand — 85.98, matching the judge’s 85.98. Verification again earned its keep: it downgraded several flagged “majors” to minor (Navigation rename, dark-theme, read-fence) after reading the code.
