## Summary
CreateEventScreen._submitForm awaits EventService.createEvent, which awaits a raw set() at event_service.dart:121. Firestore write futures resolve on SERVER ack only (#412); offline they never complete, so the eventLoadingProvider spinner spins forever — the user cannot leave the form and the event is never confirmed created (it IS in the local cache, but the UI never says so). Fix: add EventService.stageEvent returning ({Event event, Future<void> ack}) mirroring ExpenseService.stageExpense, and refactor _submitForm to stage + awaitServerAck(skipWait: status != online), treating WriteAck.queued as success (release spinner, fire activity log, noteQueuedWrite(), show a global-messenger "Saved — will sync" snackbar, navigate to the EventHub). Severity P2 (real hang; the issue's "duplicate event on re-entry" impact does NOT reproduce — eventLoadingProvider keeps LoadingButton disabled). Gate-EXEMPT: no money math / firestore.rules / Functions-auth / routing-tree / schema-field change.
