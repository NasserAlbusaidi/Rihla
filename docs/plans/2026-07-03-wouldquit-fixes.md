## PR-A — #838 offline-aware first boot

**Facts (verified):** `_AuthGate` (`lib/main.dart:130-183`) awaits `FirebaseConfig.ensureAnonymousSession()`; first-ever boot with no network throws `FirebaseAuthException(code: 'network-request-failed')` from `_signInAnonymously` (`firebase_config.dart:151-165`, rethrown). The error branch (`main.dart:166-177`) renders `SplashScreen(hasError: true, onRetry: _retry)` and (a) never classifies `snapshot.error`, (b) calls `Sentry.captureException` **on every rebuild**. `_retry` re-runs `ensureAnonymousSession()` — which is idempotent and WOULD succeed once online (cache barrier no-ops on uid==null, `firebase_config.dart:139-143`). Persisted-session boots are offline-safe already (`authStateChanges().first` from disk; unawaited non-destructive token verify #105/#213) — **first-boot-only scope confirmed.** `classifyError` (`lib/core/utils/error_message_translator.dart:34-55`) already maps `network-request-failed`/`unavailable`/`deadline-exceeded`/`TimeoutException` → `FriendlyError.network`. The splash error UI sits inside `ProviderScope` with full l10n delegates (`main.dart:174-175`). `SplashScreen` has a second consumer that must keep compiling: `_CacheIsolationApp` (`main.dart:318-330`).

**Design:**
1. `SplashScreen` gains an optional `final Object? error;` param (default null, ctor stays const-compatible). Internally: `final offline = error != null && classifyError(error!) == FriendlyError.network;` — `_ErrorBody` picks `splashOfflineTitle`/`splashOfflineBody` when offline, else the existing `splashErrorTitle`/`splashErrorBody`. Retry button unchanged (`splashRetry`). `_CacheIsolationApp` call site unaffected (no `error` → generic copy, correct there).
2. `_AuthGate` error branch passes `error: snapshot.error` through, and Sentry capture is de-duplicated: capture only when the error instance changes (store `Object? _lastReported` on the State; capture in the builder iff `!identical(snapshot.error, _lastReported)` then remember it). Same-branch defect, in-scope, named here.
3. **No auto-retry timer** (rejected: pre-auth connectivity is undetectable without a new dependency; a periodic re-attempt adds timer-in-test pain and the offline copy now makes manual retry meaningful). Retry stays manual.
4. New ARB keys EN+AR (+regenerate, commit generated — #245): `splashOfflineTitle` "You're offline" / `"لا يوجد اتصال"`, `splashOfflineBody` "Rihla needs an internet connection the first time it starts. Connect and try again." / `"يحتاج رحلة إلى اتصال بالإنترنت عند تشغيله لأول مرة. اتصل بالإنترنت وحاول مرة أخرى."`

**Files:** Modify `lib/core/screens/splash_screen.dart` (preserve the `// design-token-justified:` comment at :106-107 — theme purity), `lib/main.dart:166-177`, `lib/l10n/app_en.arb` + `app_ar.arb` + generated. ## PR-B — #839 honest restore outcome (GATE — run `/run-the-gate` on this section first)

**Facts (verified):** `restoreWithGoogle` writes `writeRecoveryOutcome(ok: true, expectedUid: result.user?.uid)` (`auth_recovery_service.dart:325-330`) — `expectedUid` is *whatever account the picker returned*; `restoreWithEmailLink` mirrors (`:398-403`). At boot, `surfaceRecoveryOutcome` (`recovery_outcome_notice.dart:17-62`) checks only `currentUid == expectedUid` (#458 swap-durability) and shows **hardcoded-EN** "Account restored." (`:61`) / "Account restore didn't complete…" (`:53`). It is invoked from `recoveryOutcomeNoticeProvider` (`recovery_outcome_notice_provider.dart:16-47`) in a post-frame callback, guarded by `cacheIsolationProvider` (`:22`), snacking via the global `appMessengerKey` (`app_messenger.dart:10`; key attached `main.dart:258`). The restored uid's Firestore cache is **empty by design** at notice time (`markFirestorePersistenceDirty` pre-swap → `CacheUidBarrier.reconcile` clears persistence on the post-swap boot, `cache_uid_barrier.dart:53-67`) — so a plain cache read false-reports "no data" offline; discrimination precedents: `fromCacheEmpty` (`activity_service.dart:77`) and the `Source.server` probe (`connectivity_provider.dart:114-131`). Data-presence answer = the same predicate the swap gates use: `groups where memberIds arrayContains uid` (`group_provider.dart:536-551`; there is NO `users/{uid}` doc — verified zero hits). The escape path for a durable user who restored the wrong account already exists: Profile → Account → Sign out (`signOutCurrentDevice`, durable-only, `profile_screen.dart:1226-1238`) → fresh anon boot → restore CTAs reappear (`showRestore = isAnonymous`, `:1148`). `RecoveryOutcome` fields (complete, from the type): `op, ok, code, atMillis, expectedUid` (`recovery_outcome.dart:38-46`); reader is one-shot clear-on-read (`:82-109`).

**Design:**
1. **No change to any write path or swap flow.** `auth_recovery_service.dart` is untouched. The fix lives entirely at the notice: after the existing #458 uid-match check passes for a restore op (`opGoogle`/`opRecover`), run a **data-presence probe** and pick one of three messages:
   - probe says **has data** → `recoveryRestoredOk` ("Account restored.")
   - probe says **confirmed empty** (server answered, zero groups) → `recoveryRestoredEmpty` ("Signed in, but this account has no groups yet. Restored the wrong account? Profile → Account → Sign out lets you try another.") — 8 s duration, no SnackBar action (text names the path; avoids #411 persist semantics entirely).
   - probe **inconclusive** (offline/timeout/error) → `recoveryRestoredOk` (current behavior; inconclusive must never scare).
2. **Probe contract (exact):** `Future<bool?> hasAnyGroupMembership(String uid)` — `FirebaseFirestore.instance.collection('groups').where('memberIds', arrayContains: uid).limit(1).get(const GetOptions(source: Source.server))` with a 4 s timeout; returns `true` (docs non-empty), `false` (server-confirmed empty), `null` on timeout/`unavailable`/any exception. Server source sidesteps the cleared-cache false-empty; `isDeleted` filtering is deliberately skipped (a membership row of a soft-deleted group still proves "this account held Rihla data" — the message, not the balance, is at stake). Lives beside the notice (new small file or in `recovery_outcome_notice.dart`), injected into `surfaceRecoveryOutcome` as a thunk param for testability.
3. **`surfaceRecoveryOutcome` signature:** becomes `Future<void>`, gains `required Future<bool?> Function(String uid) hasData` and `required String? Function() localize`-style copy resolution (see 4). The #458 mismatch branch is **unchanged and evaluated first**; the sign-out-silent and failure branches unchanged. The `currentUid()`-throws branch keeps trust-the-claim (shows `recoveryRestoredOk`, probe skipped — no uid to probe).
4. **Localization of the surface (in-scope):** the three notice strings move to ARB keys EN+AR — `recoveryRestoredOk`, `recoveryRestoredEmpty`, `recoverySwapIncomplete` (replacing the two hardcoded EN strings + the new one). Context-free resolution: `appMessengerKey.currentContext` → `AppLocalizations.of(ctx)`; if context/l10n unavailable, fall back to the EN literals (never crash the notice). The provider already owns the messenger plumbing — resolution happens there and the resolved strings pass into `surfaceRecoveryOutcome` (keeps the service context-free). The #647 bootstrap snacks (`auth_email_link_bootstrap_provider.dart:113-222`) stay as-is — separate surface, out of scope (noted in #840/#841).
5. **Race/lifecycle handling (from the mapper):** the marker is cleared-on-read before the async probe — a crash mid-probe drops the notice (accepted: same window exists today between read and post-frame). The `cacheIsolationProvider` guard is re-checked after the probe resolves (a new swap engaging mid-probe must eat the notice, not show a stale one). The messenger is a global key on an already-mounted MaterialApp, so a probe-delayed show still displays.
6. **Declared untouched (the Gate should verify, not relitigate):** `outgoingShellProvablyEmpty` + its 4 call sites (#647 bootstrap, #648 `triggerGoogleRestore`, profile advisory pre-check, #661 durable-sheet), `engageIsolation` + guaranteed `finally` restart in all three swap methods, `MainActivity.restartApp` QueuedWork drain (#456/#457), never-signOut-on-failure (#414/#213), and the #458 expectedUid mechanism itself. **No new swap entry point is added** — the empty-honest message points at the existing Profile sign-out path by name only.
