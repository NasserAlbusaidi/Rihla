# PR7 claimShadow — parity-safe redesign (#278), Gate-category

> **For the Gate (fresh-context Opus, zero history):** This is a **money + Cloud-Functions** spec — all four Gate axes. Review it against LIVE code with the 7 verification principles. The engine already exists on branch `feat/278-pr7-claim-engine` (PR #557); this spec replaces its parity-safety mechanism. Re-grep every line ref in the moment; anchor by symbol.

## Why we are here (the bug class — already defeated 3 single-agent guards)

`claimShadowEngine` (`functions/src/callables/claimShadow.ts`) re-keys a placeholder ("shadow") member's uuid identity to a real joiner's auth uid across every money doc (the mirror of `deleteAccount.ts`'s uid→tombstone re-key). On HEAD it commits the cascade **then** runs a POST-commit `verifyParity` asserting `postNet[claimer] == priorShadow + priorClaimer` per currency. Two structural defects:

1. **Divisor-shift corruption.** If the claimer is **already counted** in some event, re-keying shadow→claimer **dedups a divisor** (equal split) — `participantIds` 3→2, or `customSplitParticipants` 3→2 — so a **third party's** balance moves. The post-commit assert false-fails *after* an irreversible commit; the idempotent retry (shadow gone → `alreadyClaimed`) then **blesses the corrupted state**. Three refute rounds each found a different slot a slot-enumeration guard missed: `memberIds` → `participantIds` (round-2) → `customSplitParticipants` (round-3). The HEAD guard (`claimShadow.ts:268-269`, gate on `priorNet` key-set ∪ `memberIds`) is **known-insufficient** (round-3 refuted it).

2. **The post-commit `verifyParity` is itself buggy** — see FLAW B below.

## Code-verified facts this spec rests on (re-grep to confirm)

- **F1 — `participantIds` is NOT a standing invariant; an admin can SHRINK it.** The append-only `hasAll` superset guard is **only** on the light path (`firestore.rules:430-431`, `validEventLightUpdate`). `validEventAdminUpdate` (`:437-459`) lists `participantIds` in its `hasOnly` allow-list (`:443`) and runs only `validEventUpdateCommon()`→`validEventBase()` — **no superset guard** — so an event creator OR group creator (`requesterIsEventAdmin`, `:350-352`) can remove a uid from `participantIds`. That update does **not** re-validate child expense docs. So the CREATE-time guarantees `customSplitParticipants.hasOnly(participants())` (`:554`) and `splitDistribution.keys().hasOnly(participants())` (`:471-477`, `enforceParticipantKeys=true`) are **point-in-time, not standing**: an honest sequence (create expense with X in customSplit while X∈participantIds → admin removes X) yields `customSplit ⊋ participantIds` and a `splitDistribution` key ∉ `participantIds`. **Rounds 2/3 are honest-data-reachable corruption of real users' money, not forged-only.** The engine MUST defend them.
- **F2 — `leaveGroup`/`removeMember` never prune `participantIds`.** Both write only `memberIds: arrayRemove(uid)` + member-doc deletes (`leaveGroup.ts:114`, `removeMember.ts:163`; headers `:18-23`/`:29-32` say so explicitly), and both gate on the leaver/target net == 0 per currency. So a square-balance member can leave/be-removed yet stay in every event's `participantIds` (∉ `memberIds`, ∈ `participantIds`) — round-2's premise, honest-reachable.
- **F3 — the oracle's equal-split divisor is universe-/customSplit-/key- driven, NOT priorNet-driven** (`groupNetBalance.ts`): global/sub_group equal recipients = `[...universe]` (`:419`), universe = `new Set(participantIds)` ∪ former-financial-not-live (`:614-615`) ∪ member-gated split keys (`:617-618`); **custom** equal recipients = `customSplitParticipants` (`:416`); weighted = `splitDistribution` keys (`:397`). An **out-of-universe** split recipient's owed is **DROPPED** (`:428` `.has()` gate) — so a recipient can be IN a divisor yet ABSENT from `net`. This is exactly why a `priorNet`-membership guard leaks (round-3: claimer ∈ `customSplitParticipants`, dropped from `priorNet`, still moves the custom divisor).
- **F4 — FLAW A (regression a naive "drop the heuristic" Option-1 would introduce).** The claimer's liveness flips non-member→live during a claim (the engine deletes the shadow doc and creates a LIVE `{claimerUid}` doc, `claimShadow.ts:348-364`). That flip changes the oracle's `:615` former-financial gate **for the claimer's own identity**: a settlement keyed to the claimer in an event where the claimer is **not a participant** (a "stranded" settlement — payer was a participant at create-time, then admin-shrunk out) is folded into that event's equal-split universe **before** (claimer ∉ live members) but **dropped after** (claimer now live). A **third party** in that event silently shifts while the claimer's own total stays exactly additive → a claimer-only parity assert **passes the corruption**. HEAD catches this only because the stranded settlement forces the claimer into `priorNet`'s key-set (as 0) and HEAD checks `bucket.has(claimerUid)` by **presence**. **Retain the presence check.**
- **F5 — FLAW B (a latent bug ALREADY shipped in HEAD's `verifyParity`).** The claimer-only additive assert `postNet[claimer] == priorShadow + priorClaimer` is **mathematically wrong** under the alphabetically-last-absorbs-remainder rule (`allocateEqual` `:140-159` sorts recipients and the LAST absorbs `amount − perHead×count`). A brand-new claimer on a **non-divisible** equal split (e.g. 10.000 OMR / 3, remainder 1 subunit) where the shadow uuid was alphabetically-last but the claimer auth-uid is not (shadow ids are lowercase-hex `randomUUID()`, auth uids are mixed-case → the last identity flips for a large fraction of real claims) **relocates the remainder subunit to a different recipient**. That is the CORRECT post-state the oracle computes (sum still 0), but the literal additive assert sees the claimer off by 1 subunit → on HEAD it throws `internal` *after* the (correct) commit and the retry blesses; **as a pre-commit gate it becomes a hard false-reject of a legitimate claim.** The 23 existing tests miss it because every equal-split fixture uses divisible amounts (12000/2, 12000/3 in OMR are exact). **The remainder-hop is correct money movement and must be ALLOWED, not asserted against.**

## The design — pure-relabel precondition + extraction + exact TOCTOU backstop

**Core principle (panel consensus):** A clean claim is a **pure relabel** — the claimer occupies **no divisor-driving slot**, so re-keying shadow→claimer cannot dedup any divisor or flip the claimer's liveness-gated universe membership. Pure-relabel is a **structural** property, checkable read-only and **completely** (the divisor-driving slot set is exactly the identity-field set the oracle reads — enumerated and proven). A net-comparison gate cannot express it cleanly because the legitimate remainder-hop (F5) is real money movement that any net diff flags. So the **decision gate is a complete footprint pre-scan**, and the simulation is repurposed as an **exact** TOCTOU backstop.

### Part 1 — behavior-preserving extraction of `recomputeNet` (enables an in-memory simulation; ONE oracle, no second copy)

Split `recomputeNet` into:
- `loadGroupBalanceSnapshot(db, groupRef)` — **all** Firestore reads → plain objects: `{ groupExists, groupData, members: [{docId, data}], events: [{id, ref, data, expenses: DocumentData[], settlements: DocumentData[]}], groupSettlements: DocumentData[] }`. (Thread `event.ref` so `liveEventRefs` survives — `groupNetBalance.test.ts` asserts `liveEventRefs`/`perEventNet`/`eventCount`.)
- `computeNetFromSnapshot(snapshot)` — **pure**, zero I/O: the current `:518-672` body (universe construction, `foldEventNet`, group settlements, `finalizeNet`, `bucketizeDrill`) over the snapshot arrays. Returns the existing `RecomputeResult`.

`recomputeNet(db, groupRef)` keeps its **exact signature**: `return computeNetFromSnapshot(await loadGroupBalanceSnapshot(db, groupRef))`. **Behavior-preserving proof** = the 5 `recomputeNet` callers (`deleteGroup`, `leaveGroup`, `removeMember`, `balanceAggregator`, `claimShadow`) + `groupNetBalance.test.ts` head-on + `addShadowMember.test.ts` + the Dart parity tests (`delete_group_balance_parity_test.dart`, `group_balance_provider_test.dart`) all stay green — the same move that extracted `foldEventNet` (#366) and `groupNetBalance` from `deleteGroup` (#190). (`deleteGroupLockReaper.ts` also imports the module but only `timestampMillis`, whose export is unchanged — unaffected, run its suite anyway.) **Keep the `Money`, `timestampMillis`, and `RecomputeResult` exports as-is.** The reads at `:516/:524/:557/:565/:649` are extractable; only the per-event `expenses`/`settlements` fetch (`:565`) sits in the loop and moves into `loadGroupBalanceSnapshot`'s event mapping (the fold logic it feeds is already pure).

### Part 2 — the gate: complete divisor-driving footprint pre-scan (PRECISE, pre-commit, no writes on reject)

After capturing `priorNet` (from `computeNetFromSnapshot(snapshot)`), reject `failed-precondition` with **no writes** if the claimer is financially visible — **any** of:

1. `claimerUid ∈ asStringArray(groupData.memberIds)` **OR any member doc carries `userId === claimerUid`** — already a member. The member-doc arm closes the #53 `memberIds`-array-vs-member-doc divergence (`joinGroupByInviteCode.ts` heal path can leave a live member doc whose uid is briefly absent from the array), and — load-bearing for Part 3 — it **guarantees no pre-existing claimer member doc survives onto an accepted path**, so the sim's "drop shadow / append claimer" exactly mirrors Phase C. **Check both arms against the snapshot's already-loaded `members` (Part 1) — no fresh `.where('userId',…)` query, so no second-read TOCTOU seam.** *(D8: no real-identity merge.)*
2. `[...priorNet.values()].some(bucket => bucket.has(claimerUid))` — already holds a balance position in any currency (in-universe participant, payer, or settlement party), **by PRESENCE incl. a netted-to-zero stranded party** — this is HEAD's check, **RETAINED** (closes FLAW A / F4).
3. `claimerUid ∈` any live event's `participantIds ∪ customSplitParticipants ∪ keys(splitDistribution)` — a divisor slot the oracle **drops** from `priorNet` when out-of-universe (closes round-3 / F3; honest-reachable per F1).

This set is **exactly** the identity-field set the oracle reads to build every universe/divisor/weight (the same fields the re-key list mutates) — equivalently, "the relabel would dedup/merge a divisor array/map (terms 1&3) or flip a liveness-gated footprint (term 2)." **Transitive coverage of payers/settlement parties is load-bearing, not incidental:** a claimer who is ONLY an expense `payerParticipantId` or an event/group settlement payer/recipient (in no term-1/term-3 array) is folded into `priorNet` via the oracle's `financial` set (`groupNetBalance.ts:580-588`/`:614-615`) and group-settlement `seenUids` (`:658/:661`) → **term 2 (presence) catches it.** Do not "simplify" term 2 to a non-zero-value check — a netted-to-zero stranded party (F4) must still reject. It admits **exactly** pure-relabel claims (a brand-new invisible claimer passes; the F5 remainder-hop is allowed because it is not a collision) and rejects **exactly** the divisor-collapse class (rounds 1/2/3 + FLAW A). **Pin the coupling:** a header comment in BOTH `claimShadow.ts` (the pre-scan) and `groupNetBalance.ts` (universe construction) stating "these two move together — a new identity-bearing universe input here requires a new term there," plus tests T24/T25 below.

> **Honesty note for the Gate:** this gate's completeness is a *proof against the current oracle's identity-field set* (Part-2 readers verified it), pinned by a comment + tests — the same kind of oracle-coupling `deleteGroup`/`leaveGroup`/`removeMember` already carry. It is NOT defended by the Part-3 backstop (which only catches TOCTOU, not an enumeration miss). That is the deliberate trade: a clean proof beats a fuzzy net-tolerance for money code.

### Part 3 — simulation + EXACT post-commit backstop (replaces the buggy claimer-only `verifyParity`; TOCTOU defense, remainder-free)

- **Pre-commit — build the simulated snapshot by re-keying EXACTLY the oracle-read identity fields on deep copies. Spell it out per doc type (do not say "reuse the functions" — `participantIds` is re-keyed by INLINE code, and the per-doc re-keyers return PARTIALS):**
  - **event** → `{...ev, data: {...ev.data, participantIds: replaceUid(stringArray(ev.data.participantIds), shadowId, claimerUid).values}}`. ⚠️ The engine re-keys `participantIds` via an **inline `replaceUid`** (`claimShadow.ts:282-283`), NOT one of the helper fns — it is the single most divisor-driving field; if the sim omits it the shadow stays in the sim's universe while the cascade moved it to the claimer → `simNet ≠ actualNet` and the exact post-commit assert **throws `internal` on every legitimate claim** (retry re-throws deterministically).
  - **expense** → `{...e, ...(expenseRekey(e, shadowId, claimerUid) ?? {})}`. `expenseRekey` (`claimShadow.ts:77-111`) returns a **PARTIAL** field map (only the changed keys + the `claimRekeyAt` sentinel) or `null` — it MUST be **spread onto the full doc copy**. Treating the return as the whole doc zeroes `amountFils`/`scope`/`splitMode`/`currency` → garbage net.
  - **settlement (event AND group scope)** → `{...s, ...(settlementRekey(s, shadowId, claimerUid) ?? {})}` — same partial-merge contract. `settlementRekey` is the new pure fn extracted from the inline `rekeySettlements` body (`payerParticipantId`/`recipientParticipantId`/`createdBy` only; `payerName`/`recipientName` untouched — D7).
  - **member set** → drop every member entry whose `userId === shadowId`; append ONE live entry `{userId: claimerUid, isShadow: false}` — **do NOT set `isTombstone`** on it (Phase C `:348-355` omits it; `undefined !== true` ⇒ the oracle's `:531` gate treats it as live, matching the committed doc and test 8); set `groupData.memberIds = replaceUid(asStringArray(groupData.memberIds), shadowId, claimerUid).values`. (So `liveMemberIds`/`allMemberIds` see the claimer as live, mirroring Phase C `:348-364`.)
  - **Oracle-inert fields the sim MAY skip** (NOT read by `computeNetFromSnapshot`): `participantNames`, `createdBy`, `activity_logs`, the `claimRekeyAt`/`updatedAt` sentinels. Re-keying them changes nothing in `simNet`; not re-keying them is safe.

  Then `simNet = computeNetFromSnapshot(simulatedSnapshot)`. The member-set change is the **load-bearing fidelity item** (the oracle gates the universe on `liveMemberIds`/`allMemberIds`, `groupNetBalance.ts:527-531`/`:615`/`:618`; a footprint-less member is invisible to `priorNet`). Term 1's member-doc arm guarantees no pre-existing claimer doc on an accepted path, so the plain drop/append mirrors Phase C exactly. Cheap pre-commit sanity: assert the shadow is absent from `simNet`.
- **Commit** Phase B (batched) + Phase C (tx, `memberIds` LAST) — unchanged.
- **Post-commit:** `actualNet = recomputeNet(db, groupRef)`; assert `actualNet` **equals** `simNet` AND the shadow is absent. **Comparison contract (pin it, two foot-guns):** (a) iterate the **UNION** of currencies (`new Set([...simNet.keys(), ...actualNet.keys()])`) and, per currency, the **UNION** of uids — mirror HEAD `verifyParity:182` — so a uid/currency present in `actualNet` but absent from `simNet` (exactly the TOCTOU the backstop guards) is not skipped; (b) compare each `Decimal` by **VALUE** — `a.minus(b).isZero()` (or `.equals`), **NEVER `===`**: two `Money`/Decimal objects are never reference-equal, so `===` throws on every claim. HEAD `verifyParity:189` already uses `.minus().isZero()` — preserve that. **No tolerance / no remainder fuzz** — `simNet` already bakes in the legitimate remainder-hop, so absent a concurrent write `actualNet == simNet` by construction (both are `computeNetFromSnapshot` over the same relabeled docs). A mismatch means a write landed **between** the snapshot read and the commit (TOCTOU) → log a P0 + throw `internal` (idempotent-retryable; the next attempt re-snapshots). This **fixes F5** (the claimer-only additive assert is gone) while keeping a genuine concurrency backstop.

### Part 4 — minor eligibility hardening (panel note)

Eligibility currently checks `isShadow !== true` only. Add `isTombstone !== true` to the claimable predicate (Phase A + Phase C tx), so a forged `{isShadow:true, isTombstone:true}` doc is not claimable. Cheap; defensive (no honest path tombstones a shadow — it has no auth account to call `deleteAccount`).
