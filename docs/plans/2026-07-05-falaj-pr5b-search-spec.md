# PR-5b — Global `/search` (split from PR-5 at Gate round 2)

**STATUS: GATE CLEARED (round 3, 2026-07-05 — both reviewers 0 P1 same round).** Split out of `2026-07-05-falaj-pr5-ia-spec.md` §5 when the R2 adversary found a [P1] in its data source. Routing = Gate category; no code before a clean round. Refs #900.

**Problem (friction #3):** search exists only event-scoped (2 callsites: `ledger_screen.dart`, `event_command_center.dart` — the `ledger_search_sheet.dart` consumers); the Activity tab filters only loaded pager pages. Finding an old expense = 4 taps + recalling group AND event.

## The R2 [P1] this spec must honor

The original design read `openByGroup` (filters `!event.isClosed`, `active_journeys_provider.dart:273`) / `activeJourneysProvider` (excludes concluded trips via the `_isActive` time window, `:349-351`), so a **concluded trip was unfindable**, contradicting the feature's purpose. **Data source is therefore `groupEventsProvider` (`event_provider.dart:35`)** → `EventService.watchGroupEvents` (`event_service.dart:35-61`), which filters ONLY `.where('isDeleted', isEqualTo: false)` — closed events are kept. Iterated per group from `userGroupsProvider`. Results carry a visible scope label — l10n key **`searchScopeLabel`** (EN "Groups and events, including past events" / AR pair, same commit) — NEVER hardcoded; it is what makes the Option-B scope honest on screen.

**Listener math (R1 rubric, verified):** the always-mounted home tab already holds `groupEventsProvider(gid)` live for every group (via `activeJourneysProvider` / `addExpenseTargetsProvider`), so a route-scoped SearchScreen watching the same family adds ZERO incremental Firestore listeners on the warm path; on a COLD `/search` deep link (home unmounted) it is the sole watcher — O(G) event-list listeners, bounded and disposed on pop, NOT the #104 O(G×E) class. No #104 re-opening. Do NOT watch expense/settlement providers from search.

**Identity/exposure note (R1 adversary, verified):** group-detail's `_EventRow` already lists ALL group events (open+closed, non-participant included) to any member (`firestore.rules` events `allow read: if isGroupMember`). Search showing the same set is consistent with existing exposure — no new leak.

## Scope (v1)

- **Groups + events only** (open AND closed). Full expense search remains **Option C** — needs a server index (denormalized token field or external index); do NOT hand-roll a client full-scan and do NOT fan out live expense listeners. File the Option-C follow-up issue when this PR opens; the friction-#3 tap-table claim ("find old expense 4→2") belongs to Option C, not v1.
- **Match predicate (pinned):** case-insensitive substring — `haystack.toLowerCase().contains(q.toLowerCase())` — over `group.name` and `event.name` ONLY. No diacritic folding in v1 (Arabic has no case; exact substring applies). Pin with an EN + an AR match test.
- **Empty/absent `q` (pinned):** render the search field with `searchHint`; NO results sections and NO empty-state until `q` is non-empty. `searchEmpty` is exclusively the non-empty-query-zero-matches state, and is STATIC — no `{query}` ICU placeholder (unlike the sibling `activitySearchNoMatchesMessage`). Cold `/search` (no `q`) = the same hint state.
  - **> REVERSED by #1012 (2026-07-07):** the blank pre-query panel is replaced by muted pre-query guidance (a search glyph + the reused `searchScopeLabel` line) via `_PreQueryGuidance` (`SearchKeys.preQueryGuidance`). `searchEmpty` (non-empty-q zero-matches) and the results scope label remain non-empty-query only — only the blank-panel half of this pin changed.
- Route: top-level `AppRoutes.search = '/search'`; **`pageBuilder` + `CustomTransitionPage(key: state.pageKey, …)`** with the same shared-axis transition idiom as the other top-level routes in `app_router.dart` (NOT a bare `builder`) → `SearchScreen(query: state.uri.queryParameters['q'])` — query in the QUERY param, never `extra`; `/search?q=alps` cold-linkable. Typing updates results locally; the field seeds from the param (no need to push every keystroke into the URL).
- **Event-row shape (R2 rubric):** event name + the PARENT GROUP name as subtitle (+ `searchEventEnded` badge when `isClosed`). In group-detail the group is implicit; in cross-group search it is not — two "Dinner" events in different groups must be distinguishable. Group rows: group name ONLY in v1 — the "member/event count" idea is DROPPED (R3: it would be a rendered, pluralized string outside the l10n inventory; Arabic has 6 plural categories — if ever built, it needs ICU-plural EN+AR keys first).
- Result taps: group → the §2 smart-forward CONTRACT below; event → `context.push('/group/$gid/event/$eid')` (works for closed events — the hub renders closed events with the Recap tab available, `event_command_center.dart:202` `showRecap = event.isClosed`).
- **Smart-forward contract (spelled out — the rule is INLINE in `home_screen.dart:196-210`, not a shared helper):** SearchScreen watches `addExpenseTargetsProvider`; group-row tap does: `final open = targets.openByGroup[gid]; final soleEvent = (targets.allResolved && open != null && open.length == 1) ? open.single : null; context.push(soleEvent != null ? '/group/$gid/event/${soleEvent.eventId}' : '/group/$gid');`. Duplicating the inline rule is acceptable (extracting a shared helper is optional, NOT required). Note `openByGroup` is OPEN-events-only BY DESIGN here: a fully-concluded group forwards to `/group/$gid` (the group overview), which is correct — its events are reachable there.
- **Back-guard [R1 P1 fix]:** `/search` is a TOP-LEVEL, ROUTE-ONLY screen — its governing precedent is **`GroupDetailScreen`** (`group_detail_screen.dart:66-76`), NOT the #666 dual-mode rule (that rule exists for screens that are ALSO BottomNavShell tabs; `/search` is never a tab). Cold/restored entry makes `/search` the sole stack page (`canPop()==false`), where the Android system-back GESTURE — not just the app-bar button — must go home, not exit the app. Therefore: `PopScope(canPop: false)` + `onPopInvokedWithResult: (didPop, _) { if (didPop) return; context.canPop() ? context.pop() : context.go('/home'); }` (mirror GroupDetailScreen's exact shape), and the app-bar `_back` uses the same `canPop() ? pop() : go('/home')`.
- **Closed-event badge [R1 P2 fix]:** NO row-level closed marker exists anywhere today (`_EventRow` renders type/name/date/amount with no closed state; the only closed markers are the event-hub banner `eventClosedBanner` and recap captions — a banner sentence, not a row badge). So: add a NEW compact badge — l10n key `searchEventEnded` (EN "Ended" / AR pair, both arbs same commit) — echoing the ledger `SETTLED` pill *style* (pill container idiom, not its key). Gate it on `event.isClosed` (event lifecycle), never call it "settled" (that's a balance state).
- Entry point (decided): search icon in the home top bar (`Iconsax.search_normal` — magnifier glyphs are conventionally do-not-mirror and the codebase already renders it un-flipped in RTL, e.g. `cross_group_activity_screen.dart:244`; no RTL flip). Tap → `context.push('/search')`. The search `_IconCircle` MUST carry `semanticLabel: context.l10n.searchTitle` (the bell beside it is labeled — an unlabeled sibling is an a11y regression; reusing `searchTitle` keeps the inventory at 7 keys). The home `_TopBar` is a private per-screen class, so the affordance is home-only — no profile/activity top-bar changes. **Composition note (R2 adversary):** the bell is currently the sole right-cluster icon and the wordmark is centered by twin Spacers (`home_screen.dart:552-568`); adding the search `_IconCircle` shifts the wordmark off-center — accept the shift (avatar left vs bell+search right) and REGENERATE the home goldens locally (macOS-only, CI-excluded — a silent-stale risk, not a red-CI one). The Activity tab's local filter (`activitySearchClose`) coexists by design: it filters loaded activity pages; `/search` finds groups/events globally — different scopes, both stay.
- Any forward chevron on result rows must be `DirectionalIcon` / explicit RTL flip (standing Do/Don't).
- Not in the BottomNavShell: `/search` renders WITHOUT the bottom-nav (a pushed top-level route, same as `/group/:gid`).
