## Goal

Gate **creation**, not **participation**. An anonymous user may join a group by invite code and add expenses on their own device. Keep the durable-credential gate on group-create and invite-code-create (the creator is always recoverable). The "back this up" prompt is a contextual nudge, not a door.

## Why it's safe (no rules surgery for money)

The money write rules already key on **participation**, not durability — re-verified in code 2026-06-23:

| Rule | Gate | Line |
|---|---|---|
| `validExpenseCreate` | `isEventParticipant(groupId, eventId)` | `firestore.rules:620` |
| `validEventCreate` | `isGroupMember(groupId)` | `:421` |
| `validEventSettlementCreate` | `isEventParticipant(groupId, eventId)` | `:759` |
| `validGroupSettlementCreate` | `isGroupMember(groupId)` | `:957` |
| `validGroupCreate` | `isDurableSignIn()` — **KEEP** | `:270` |
| `inviteCodes/{code}` create | `isDurableSignIn()` — **KEEP** | `:211` |

Anon-can't-write-money today is purely downstream of both membership-origination paths being durability-gated. Drop the join gate and anon-participation falls out for free. No money rule changes; no `firestore.rules` change at all (the kept gates already encode the desired policy).

### 6. [P1 — Gate R1] Guard the Google voluntary-restore swap at the swap point, not on CTA visibility

- Home empty-state (`home_screen.dart:313-328` → `triggerGoogleRestore`) — rendered in the `data: groups.isEmpty` branch (`:98`), **no `isAnonymous` check**.
- Profile (`profile_screen.dart:1099-1100,1195`) — `showRestore = isAnonymous && userGroupsProvider…valueOrNull?.isEmpty`.

Both gates read `userGroupsProvider`, which **false-empties on cold start**: `firebaseUserProvider` (`group_provider.dart:603-605`, an `authStateChanges()` stream) is `AsyncLoading` on first paint → `userGroupsProvider` (`:612-618`) yields `Stream.value([])` → resolves to **`AsyncData([])`** (masquerades as settled data, *not* `loading`) → the home `data:` branch shows the empty state + restore CTA → one tap → ungated swap → **total silent ledger loss**. This is the identical race #647 fixed for the email path, left open on the Google path. It was latent only because an anon shell could never be populated — **#648 removes that invariant**, so #648 must close it. The home comment (`:316-318`) literally encodes the now-false "empty state ⇒ zero groups ⇒ no money data."

## Verification principles (run while authoring)

1. **Callsite classification.** Only write path touched: `joinGroup → joinGroupByInviteCode` (OUTBOUND, member-doc + memberIds write). Removing the anon gate writes an anon UID as a member — **same shape** as a durable UID; no INBOUND reader special-cases provider. No data-shape change.
2. **Concrete claims vs code.** Every line number above re-verified by Read/grep this session, not from memory or the issue.
3. **One read-path per write-path.** Write: anon member doc. Read: `recomputeNet` oracle universe = `participantIds ∪ (payers+settlement parties \ live)` — an anon member key is treated identically to any uid; balances and the home aggregate (`balanceAggregator`) compute unchanged.
4. **Fields from the type.** No new/changed fields. Callable input (`inviteCode`, `displayName`) and member-doc shape unchanged.
5. **Data contracts.** Callable signature byte-identical. Sole change: delete the provider check. Downstream member write is identical regardless of provider.
6. **Arithmetic decomposition.** N/A — no math change. An anon uid is just another key in `paidMap`/`owedMap`; per-currency buckets, remainder→alphabetically-last unaffected.
7. **Adversarial pass (orthogonal axis = money-flow × identity over time).**
   > Anon UID-A joins group G (un-gated), adds expense E: pays OMR 30, equal 3-way {A,B,C} → A is owed 20.000. Shell now populated. A taps the home nudge → Continue with Google → that Google acct is already UID-B → **conflict**. Sheet watches `userGroupsProvider` → `[G]` non-empty → **no switch offer** (shows "use a different account"). A's ledger is safe. Or: A signs in with a *fresh* Google acct → `linkWithCredential` in place → UID unchanged → A still owed 20.000, now durable. The auth-axis change (anon participates) is safe *because* the identity-axis guards (swap requires empty shell) hold. TIME axis: join is a callable (online-only); unlike create it stages no offline batch, so there is no offline-replay-past-gate path.
