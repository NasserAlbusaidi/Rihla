#355

design(loading): replace first-paint spinners with existing skeleton loaders (~8 screens)

P2 · performance · design · primitives already exist

Pure UI swap. The current _LoadingState on each list screen paints a colored header band + a centered spinner; the skeleton variant reuses SkeletonLoader.expenseList (ledger) and SkeletonLoader.eventCard (group detail) so the placeholder mirrors the real layout and the screen doesn't jump when data arrives. Modal-blocking spinners stay as-is (sign-in, button submit) — those gate an action, not a list read.

Recommendation: ship the after on every cited list screen — content-shaped skeleton beats a spinner on perceived speed and removes the load → empty layout jump. No competing design; the only choice is fidelity, and the named factories already encode it.
