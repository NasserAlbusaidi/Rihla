#352 · Ask before the ask

Right after a successful join or create (#288), NotificationPrompt.maybePrompt() jumps straight to the Android system permission dialog — zero context. A cold OS prompt with no "why" gets denied, and a denial is permanent. These variants insert a soft in-app rationale before the OS dialog: Not now sets notificationPromptSeen and never nags; only Turn on calls notificationService.initialize(). ← gallery

#352

design(notifications): soft in-app rationale before the OS push prompt

P2 · design · builds on #288

All three keep the same contract — Turn on is the only path that triggers the OS dialog, Not now persists notificationPromptSeen so the soft ask never repeats. They differ on surface and weight: a full illustrated sheet that sells the value, a minimal one-liner sheet, or a dismissible inline card on Home that waits for a calmer moment instead of interrupting the success screen.

Recommendation: Variant 1 (illustrated rationale sheet) — the value bullets earn the OS prompt, which lifts grant-rate; it's the lightest lift (a new showModalBottomSheet in front of the existing maybePrompt() call) and keeps the moment-of-relevance from #288.
