#204 · Before you settle review sheet

When someone taps Settle up (or closes the trip), Rihla checks the ledger and — only when some expenses are review-worthy (exact split, custom participants, an excluded member, an unusually large bill, a personal-only line, a recent edit) — shows a calm, non-blocking sheet before pushing /group/:gid/event/:eid/ledger/settle-up. If every expense is an ordinary equal split the sheet never appears. All three variants intercept the same CTA in ledger_sticky_cta.dart → onSettleUp. #204

money/ux: add pre-settlement review sheet for unusual expenses

P2 · money · design · cluster:settlement-ux

All three share the same trigger logic and the same two actions (Review expenses · Continue to settle) — they differ on density. V1 lists compact rows each tagged with a reason pill (EXACT, CUSTOM, LARGE, PERSONAL, EDITED). V2 makes each flagged expense an expandable card showing the split inline. V3 leads with a one-glance count summary and folds the row list behind a single expander. The fourth phone proves the no-flags path: an all-equal-split ledger taps straight through with no sheet at all.

Pill taxonomy: EXACT — payer specified exact amounts; CUSTOM — non-standard participant set (excludes a member or adds extras); LARGE — top-N by amount relative to event total; PERSONAL — single-person expense; EDITED — expense modified after initial entry. All text is neutral, non-accusatory. Arabic/RTL: same sheet, [dir="rtl"] applied to the modal — Reem Kufi replaces Instrument Serif for the title.

Recommendation: Variant V1 (checklist sheet) — reason pills carry "why flagged" at a glance, rows stay scannable, and each row deep-links to the expense edit surface. Lowest implementation cost path to all acceptance criteria.
