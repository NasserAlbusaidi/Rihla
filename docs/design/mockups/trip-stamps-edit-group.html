Rihla · Group identity · PR-3

Restamping a group

Trip Stamps lets you choose a symbol + ink when you create a group. PR-3 is the missing half: a creator coming back to change the stamp on a group that already exists. The question this board answers — where does that edit live, and does the name come along for the ride?

01 / Proposed flow

The pencil already on the stamp opens one “Edit group” sheet

Group settings already stacks a creator-only ✎ badge on the group stamp. Today it only renames. We let it open a single identity sheet — the same hero · ink · symbol layout as Create, plus the name field — seeded from the group’s current stamp. ◆ Recommended

02 / The decision

One identity sheet, not two editors

The ✎ already means “edit this group.” Folding the name into the same sheet as the stamp keeps a single mental model, mirrors the Create screen exactly, and lets one atomic write carry name + symbol + ink (the rules already allow them together). The alternative keeps the diff smaller but splits identity across two affordances.

A · Combined “Edit group” sheet
◆ Recommended
For
  • Matches the signed-off Create & edit sheet 1:1
  • ✎ keeps one meaning: edit identity
  • Name + stamp = one atomic write, one Save
  • Nothing new to discover on the tile
Against
  • Inline rename relocates into the sheet
  • Rewrites the 3 existing name-edit tests
B · Stamp-only sheet (tile becomes tappable)
For
  • Smallest diff; rename path untouched
  • No existing tests change
Against
  • Two tap targets on one 44px tile (✎ = name, body = stamp)
  • “Tap the tile” is undiscoverable & undrawn
  • Identity edited in two different places
Both write the same data. The split is purely where the creator taps and whether rename moves.
03 / Back to the monogram

Removing a symbol returns the serif initial

The first symbol cell is the no-symbol default: the group’s initial in the serif. Selecting it clears the stored symbol (the field is deleted, not blanked) so the tile is byte-identical to a group that never picked one. The same is true for ink — clear it and the colour derives from the name again.

Symbol chosen
Wave · Harbour — stored as glyph:'wave', inkIndex:1
Symbol removed → monogram
S Initial returns — glyph field deleted, ink kept

Creator-only

The ✎ is already gated to the group creator. Non-creators never see the affordance and the rules reject a non-creator stamp write, so the sheet inherits that gate for free.

No new route

It’s a bottom sheet over Group settings, not a screen — nothing to deep-link, nothing to guard on back. The sheet reuses the exact picker built for Create.

Live hero

The hero restamps as you tap — symbol, ink, and the name’s initial all update in place, so Save never surprises you. Identical behaviour to the Create hero.

Rules already shipped

PR-2a deployed the allow-list and creator-edit guard for glyph/inkIndex. PR-3 is client-only — no backend change.
