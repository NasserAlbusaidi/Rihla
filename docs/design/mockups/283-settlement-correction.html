#283 · Fix a wrong payment

Settlements are append-only by design (settlement_service.dart — no delete, no edit; invariant B3). But the payment-history tile in settle_up_page_body.dart (_HistoryTile) is fully inert, so a non-technical user who records the wrong amount, person, or payee has no discoverable way to fix it — and won't intuit "record an offsetting reverse payment." The correction must add a reversing entry, never delete or edit. Question: how do we surface it without breaking append-only? ← gallery

#283

feat(settle-up): discoverable correction for a mistaken settlement (offsetting entry; keep append-only)

P2 · money · design · enhancement

All three variants live on the existing Payment history footer beneath "Each person's net". None deletes or edits the original row — every path writes a new reversing settlement (Layla → Ahmed OMR5.000 becomes a fresh Ahmed → Layla entry). They differ only on how the correction is discovered and how clearly the append-only mental model is taught at the moment of action.

Recommendation: Variant C (correction sheet) — it previews the reversing entry and says in plain words "we add a reversing entry; the original stays in history, nothing is deleted," giving the clearest mental model before anything is recorded.
