#349

polish(a11y): skeleton shimmer ignores reduce-motion (MediaQuery.disableAnimations)

P3 · design · a11y

Both phones show the same home loading skeleton (balance hero, journeys, groups list). The only difference is the OS reduce-motion setting: on the left the gradient sweeps left→right (the shimmer keyframe); on the right it's a flat neutral fill with no animation. Nothing else — layout, sizing, colors — changes. There is no design choice to make here; the recommended treatment is to gate the animation on MediaQuery.disableAnimations.

Recommendation: ship the gated behavior — when reduce-motion is on, swap .skel for .skel.static. This is the fix, not a competing direction.

The fix. When MediaQuery.disableAnimations is true, render the identical skeleton with the shimmer keyframe disabled — a flat --paper-deep fill (here, .skel.static). Same shapes, no motion, so vestibular-sensitive users see a calm placeholder. Implement by passing reduce-motion into the ShimmerEffect (or swapping to a no-op effect) at skeleton_loader.dart:309; the home Skeletonizer at home_screen.dart:363 reads MediaQuery.disableAnimationsOf(context) and passes the flag down. A widget test wraps the skeleton under a MediaQuery override with disableAnimations: true and asserts no ShimmerEffect (or that the static branch is rendered) — this is AC 3 of the issue and must ship alongside the implementation.
