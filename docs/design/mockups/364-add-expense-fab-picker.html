#364

design(ledger): persistent Add-expense FAB with group→event picker

P2 · decision · routing surface · Gate before build

All three put a saffron FAB on the BottomNavShell (over Groups + Activity tabs). They differ on how a context-free tap resolves the target event: V1 walks an explicit two-step sheet (group, then event); V2 jumps straight into add for the last-active event with a Change escape hatch; V3 expands the FAB into recent group/event shortcuts. Every path ends at the same route — /group/:gid/event/:eid/ledger/add — so back-guard and deep-link behavior is identical regardless of which UI ships. No state.extra in any variant; all navigation is path-based so cold deep-links work.

Recommendation: Variant V2 (quick add, last-active) — one tap to the add screen for the common case (you're logging into the trip you're already on), with Change for the rest. Fewest taps where it matters.

FAB → modal sheet, group then event. A predictable, zero-guessing flow: step 1 lists your groups, step 2 lists that group's events, tapping an event routes to /group/:gid/event/:eid/ledger/add. The slowest of the three (two deliberate taps before the form) but the only one that never picks the wrong target for you. Implement as a stateless showModalBottomSheet off the BottomNavShell FAB; each tap context.pushes the next path segment — no state.extra.

FAB opens add, pre-targeted to your last-active event — the trip you're already living in — with a Change ▾ link that drops to the V1 picker for the rare miss. Single tap to a fillable form for the 90% case. The "last-active event" is a SharedPrefs pointer ({gid, eid}) updated on every successful ledger write; if it's empty/stale the FAB falls through to the V1 sheet. Change and the empty fallback both route the same path-based way — no state.extra. All amounts shown in OMR (3 dp, code-first, monospace).

FAB expands into a speed-dial of recent group→event targets. Tap the FAB, pick a recent event shortcut, land in /group/:gid/event/:eid/ledger/add — bypassing the group step for the events you touch most. Visually rich but heavier: a vertical speed-dial scales badly past ~4 entries and the "More…" tail still falls back to the V1 sheet, so it's two flows to build and test.
