#364 · Add-expense FAB → group → event

Logging a spend takes 3+ taps today (home → group → event hub → Ledger → + Add expense). A persistent FAB on the Groups/Activity tabs shortcuts the app's most important action — but expenses are event-scoped, so a tab-level FAB has no event context and must resolve a target group → event before it can route into /group/:gid/event/:eid/ledger/add. #364

design(ledger): persistent Add-expense FAB with group→event picker

P2 · decision · routing surface · Gate before build

All variants put a saffron FAB on the BottomNavShell (over Groups + Activity tabs; hidden on Profile). They differ on how a context-free tap resolves the target event: V4 opens one flattened sheet of open events across all groups; V1 walks an explicit two-step sheet (group, then event); V2 jumps straight into add for the last-active event with a Change escape hatch; V3 expands the FAB into recent group/event shortcuts. Every path ends at the same route — /group/:gid/event/:eid/ledger/add — so back-guard and deep-link behavior is identical regardless of which UI ships. No state.extra in any variant; all navigation is path-based so cold deep-links work.

Decision (2026-07-02): V4 — flattened events sheet, with a single-candidate fast path. Rows reuse the home journey-strip ordering (ongoing → upcoming → recent), so the trip you're living in is the first row — one tap slower than V2's last-active jump but it never silently files a spend into the wrong event, and it needs no new persistence (V2's last-active pointer doesn't exist anywhere today). When exactly one open event exists across all groups the sheet is skipped entirely — straight to the add screen, whose Where card already names the event. Closed (isClosed, #723) and soft-deleted events never appear. V1/V2/V3 below kept for the record — superseded.

V4 edge states

fast path · browse-all fallback · zero-groups empty

The sheet's three boundary conditions. Fast path: exactly one open event across all groups (the #245 new-user shape — one group, one seeded event) → the FAB skips the sheet and pushes the add screen directly; its Where card names the target so there is no ambiguity. Browse-all: the footer row slides the sheet to a group list → that group's open events (V1's two-step, reached only on demand). Empty: no groups at all → the sheet explains and offers Create group.
