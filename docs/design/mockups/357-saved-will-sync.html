design(offline): surface the dead syncing state as "Saved — will sync"

P3 · design · copy/state fix · no visual fork

This is a treatment, not a design fork: there is one correct behaviour — give the already-defined syncing state a banner, and put OfflineBanner on the screens that write money. Variant A shows the full state set (offline → syncing → online) across three phone frames so each transition is legible. Variant B shows the syncing banner in situ on the add-expense write surface — the acceptance criterion that is currently unmet. The only real decision is tone: the .banner.sync token is saffron-soft (calm, reassuring) vs the amber .banner of offline (caution) — both already exist in rihla.css.

Recommendation: Variant A (the three-state strip set) — it is the literal acceptance criterion: the dead syncing state surfaces a transient "Saved — will sync" affordance, distinct in tone from offline, gone when online. Variant B shows the same fix live on the add-expense surface — both ship together.
