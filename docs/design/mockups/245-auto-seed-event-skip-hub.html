#245 · Group → add expense, no hub

Today a fresh group makes you create an event container, name it, then tap through the EventCommandCenter hub before you can log a thing — ≥3 taps + a naming decision for the ~90% one-trip case. Post-Phase-39 an event is just a ledger-only scope, so that tier is pure activation tax with no payload. Auto-seed one default event on createGroup and skip the hub for single-event groups so the path collapses to Splitwise's group → +. UX-only, no data-model change; the multi-event model survives for the minority who need it. ← gallery

V2 keeps a thin event strip above the ledger. V3 uses an empty-state teaching card. The hub (EventCommandCenter) only reappears once a 2nd event exists.

Recommendation: Variant 1 (Collapsed) — drop onto the ledger with a prominent + Add expense; a quiet Events (1) affordance reveals the hub only when ≥2 exist. Closest to Splitwise parity and removes every interstitial from the first-expense path.
