#242 · Real per-person split preview

The expense editor's Split between card always shows the equal figure (amount ÷ count) and a "{amount} each" chip — even when the user picked Shares, Exact, or Percent. The split is persisted correctly; only the preview lies. The "Before" frame shows the current broken state. Both fix variants thread _splitMode + _splitDistribution into _SplitPreviewCard and call the new public pure allocateOwed() extracted from BalanceCalculator. Worked here: Shares 2:1 on OMR30.000 and Percent 60/40 on OMR27.500. ← gallery

#242

feat(ledger): split preview shows real per-person amounts (WYSIWYG)

P3 · money · Gate-required · l10n

The fix requires extracting a public pure allocateOwed() from BalanceCalculator so the preview and the persisted calc share one copy of the allocator (remainder → alphabetically-last recipient, negative-owed guards, tolerance). Threading mode + distribution into _SplitPreviewCard then drops the misleading editorEachAmount chip for non-equal modes. Both variants implement the same math; they differ only on how the non-uniform total is surfaced. Per-tile Directionality.ltr (#151) and the count < 2 guard are preserved in both.

Recommendation: Variant 1 (Per-person list) — the whole bug is that one blended number hides reality; the fix is to stop summarising and show the real figures by default, not behind a tap.
