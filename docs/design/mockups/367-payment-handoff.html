#367

feat(settle-up): payment handoff — WhatsApp / IBAN / QR

design · privacy · decision · needs payment-handle schema (ADR)

All three variants add a handoff layer above the existing record step and keep the "Rihla doesn't move money" framing. They differ on where the channels live: a dedicated handoff block inside the Mark-paid sheet (V1 — pick), an inline Pay via strip on each settle-up row (V2), or a QR-first hand-the-phone moment (V3). The IBAN is always shown redacted (middle masked); copy fires a SnackBar. Schema (member doc vs profile, PII treatment) is decided in the ADR — these mock the UI only. Gate-category change: schema + write-adjacent → Gate required before implementation.

Recommendation: Variant 1 (Handoff sheet) — channels sit where the user already is (confirming a payment), reuses the existing _MarkPaidSheet + shareText path, and degrades gracefully when a creditor has no IBAN on file.
