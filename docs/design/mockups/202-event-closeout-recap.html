#202 · Event closeout + trip recap

Once an event is explicitly closed by an admin (never derived from dates) it earns a read-only Closeout reached from the event hub / ledger. Two layers: a restrained accounting summary users can trust, and a polished "wrapped" recap they can review and share via shareText. Spending is snapshot-frozen at close; settlement status stays live. Which is the screen, and which is the artifact? ← gallery

#202

money/ux: add event closeout summary and shareable trip recap

P2 · post-release · money + design · cluster:settlement-ux

All three render the same closed event — Wadi Shab Weekend, OMR 142.350 across 5 people — so the only fork is the frame. V1 treats closeout as an accounting receipt. V2 treats it as a celebration. V3 makes the accounting the screen and the celebration the shareable card behind one Share recap button — trust first, delight opt-in. New EventCloseout screen at /group/:gid/event/:eid/closeout; reuses BalanceCalculator + shareText.

Recommendation: Variant C (hybrid) — the money summary is the destination users return to; the wrapped card is an optional share artifact, not the primary surface.
