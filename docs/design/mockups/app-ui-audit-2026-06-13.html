Rihla · honest app-UI audit

Mapped the whole app from the live screens (not the aspirational mockups) and pinned the real rough edges. The verdict up front: the visual language is genuinely good — saffron-on-paper, the serif-italic voice, mono money, the ticket-card metaphor. None of that needs changing. The problems are structural and consistency-level: the app restates the same balance three ways on every money screen, the split editor previews a number that can be wrong, navigation is one hub too deep, and loading/error states drift screen-to-screen against your own DESIGN.md §10 contract. Each block below is a NOW (what the code renders today) beside a BETTER built on the same rihla.css tokens. Pick what's worth filing.

A1

The split preview can show the wrong per-person amount

money-wrong

Adding an expense is split across three stacked sections — “Paid by”, “Split between” (who), “How” (the math). The “Split between” card always previews amount ÷ count as “X.XXX each” (_SplitPreviewCard, expense_editor_body.dart:43) — it never reads the chosen split mode. So when you weight a split by shares/exact/percent in the “How” sheet, the preview still says the equal figure, and the ledger row then hides the per-head share entirely for non-equal splits (ledger_day_card.dart:311). The user can set a weighted split and never see a true per-person number anywhere. There are also two separate payer pickers (“Paid by → Change” and a second dropdown inside “Customise”).

  • Fix: one Split card that is the single source of truth — payer inline, mode as a segmented control, and real allocateOwed figures per person that update live with an “adds up to TOTAL” reconciliation footer.
  • Kill the second payer picker. Show your own share, highlighted. This is exactly the WYSIWYG intent of #242/#203 but applied to the everyday flow, not a helper.

A2

Every money screen restates your balance three ways

clarity

On group detail, the hero shows your net, and then the Members card lists everyone’s net including yours again, tagged “You” — the same number twice with no link between them. The ledger does the same with a serif prose hero + a roster strip + a mono “trip total” caption (three visual languages for balance in the first ~280px). Settle-up stacks a headline + a summary card + “each person’s net” + transfer cards. And group detail has two “New event” buttons ~40px apart (the hero CTA and the section header action).

  • Fix: the hero owns your number once, with the counterparties named inline (“Ahmed & Sara owe you”). The people card becomes a roster — others’ nets, and your own row just says “You” without repeating the hero figure.
  • One “New event” entry (section header). Hero CTAs are the two verbs that matter: Settle up + Add expense.

A3

Profile says “Anonymous traveller” even after you back up — and hides the one thing protecting your data

clarity

The identity hero hardcodes the tagline profileAnonymousTraveller (profile_screen.dart:405) with no branch on durability — a user who linked Google or email still reads “Anonymous traveller.” Meanwhile “Linked email — Not set” renders as a neutral grey row (:942), identical in weight to a benign preference, despite being the single guard against anonymous data loss. Restore entries are scattered across a pending banner, two account rows, and a credential sheet.

  • Fix: a status chip in the hero — amber “⚠ Not backed up” for anon, sage “✓ Backed up · email/Google” once durable. The hero tells the truth about your account state.
  • When anon, a single “Back up this account” card states the stakes (“your trips live only on this phone”) and routes to link. Group recovery/restore under one labelled block; delete stays in its own danger zone.

A4

Loading & error states drift screen-to-screen (and one error lies)

consistency

Your DESIGN.md §10 says every async surface needs all four states with a layout-matched skeleton. In practice: the cross-group Activity feed shows a blank screen while loading (cross_group_activity_screen.dart:69), Create-event shows a bare spinner (create_event_screen.dart:227), the Profile stats show em-dashes with no loading/error state, and the group Activity screen swallows fetch errors (group_activity_screen.dart:104) so a network failure renders “No activity yet” — telling the user the group is empty when loading actually failed.

  • Fix: the SkeletonLoader you already built, everywhere first-paint loads; EmptyStateView for empties; and a real error card with Retry that never masquerades as “empty”.

A5

Creating an event is three screens to reach a ledger

clarity

Type picker → details form → command-center hub. The type picker exists only to set one enum before the form (event_type_picker_screen.dart), and it pre-selects “Trip” anyway. That’s a whole screen earning its place by holding a single choice. (The hub itself is content-rich and stays — the redundancy worth removing is the picker, not the hub.)

  • Fix: fold the type into a chip row at the top of the create form — one screen to create an event. Saves a tap and a transition on the single most common creation flow.

System hygiene — small drifts, one consistent system

consistency

Not worth phone frames — but these add up. The same patterns are hand-rolled per screen and have quietly diverged. Each is a small, mechanical consolidation against tokens you already have.

Header heights drift: 36 / 44 / 48px

Join (36), settings (44), settle-up/activity (48) — and the back affordance is a different widget on each (paper-circle, ghost-icon, plain IconButton, Material BackButton/CloseButton, filled-square).

Four+ avatar widgets

RAvatar, _Avatar, _MiniAvatar, and a stock CircleAvatar in the payer dropdown — slightly different sizes/colors for the same person.

→ RAvatar everywhere; DEC-3 already mandates one stable color per person.

Activity rows rendered three ways

Home “Recently”, the cross-group feed, and the per-event feed all consume the same data through three different row widgets — and the cross-group feed’s selected filter chip uses near-black, not saffron.

AllAll

→ One shared ActivityRow + saffron selected-chip everywhere.

Dead / inert affordances

The create-group glyph row looks like a picker but selects nothing (_GlyphRow, no onTap). Group-settings “Defaults” hardcodes “Equally / Weekly”. Settle-up collects a payment method that’s never persisted. Payment history can’t be corrected.

→ Wire them (glyph picker = #287) or remove them. Don’t ship controls that do nothing.
